# 서류 평가 관리 화면 크기·여백 규칙

서류 평가 관리의 모든 화면(전체 지원 현황, 분석·시각화·엔지니어링 서류 평가, 합격자 부원 등록, 지원자 평가 화면, 지원서 상세 창)에 공통으로 적용한 글자 크기·컨트롤 높이·표 여백·카드 간격 규칙을 정리한다. 같은 규칙을 다른 화면에 옮길 때 이 문서의 순서를 따른다.

- 기준일: 2026-11-21
- 코드: `src/app/styles/review-design.css` 맨 아래의 `.evaluation-scale` 블록
- 화면 동작(무엇이 보이는가)은 [`03-evaluation.md`](03-evaluation.md)에 있다. 이 문서는 크기와 배치만 다룬다.

---

## 1. 전제: 이 앱의 rem은 14px이다

`src/app/styles/theme.css`가 `html`의 글자 크기를 14px로 정한다. 그래서 `1rem`은 14px이다. 디자인 수치를 16px 기준 rem(예: 표 글자 0.875rem = 14px)으로 정했다면, 그 값을 그대로 쓰면 12.25px가 되어 의도보다 작아진다.

`html` 글자 크기는 앱 전체에 영향을 주므로 바꾸지 않는다. 대신 범위 클래스 안에서만 16px에 해당하는 rem 단위를 변수로 둔다.

```css
.evaluation-scale {
  --u: calc(1rem * 16 / 14); /* 16px에 해당하는 rem */
}
.evaluation-scale .review-list-table {
  font-size: calc(0.875 * var(--u)); /* 14px */
}
```

이렇게 쓰면 디자인 수치(0.875, 1.5 등)를 그대로 읽을 수 있고, 브라우저 확대·사용자 글자 크기 설정에도 함께 커진다.

## 2. 적용 방법

### 2.1 범위 클래스

| 클래스 | 붙는 곳 | 역할 |
| --- | --- | --- |
| `evaluation-scale` | `EvaluationManagePage` 최상위, `ApplicantReviewDetail` 최상위 | 모든 규칙의 범위. 이 클래스 밖(출결·콘텐츠 등)에는 영향이 없다 |

모든 규칙은 `.evaluation-scale` 아래에만 쓴다. 공통 컴포넌트(`FilterDropdown`, `SearchInput`, `RefreshButton`, `SelectDropdown`)의 코드와 전역 스타일은 바꾸지 않고, 범위 안에서만 크기를 덮어쓴다. 다른 화면이 같은 컴포넌트를 쓰고 있기 때문이다.

### 2.2 화면 쪽에 붙이는 클래스

규칙이 요소를 찾을 수 있도록 화면 코드에는 이름만 붙인다. 이 클래스들은 범위 밖에서는 아무 스타일도 갖지 않는다(`review-search-group`만 기본값 `display: contents`).

| 클래스 | 붙이는 요소 | 쓰는 화면 |
| --- | --- | --- |
| `review-list-toolbar` | 표 위 도구 줄(필터·정렬·검색·새로고침) | 세 목록 화면 |
| `review-search-group` | 검색창과 새로고침을 감싸는 `div` | 세 목록 화면 |
| `review-list-table` | 목록 표 `table` (글자·셀 여백·행 드롭다운 공통) | 세 목록 화면 |
| `review-eval-table` | 서류 평가 표 `table` (열 너비) | 분석·시각화·엔지니어링 |
| `review-register-table` | 합격자 부원 등록 표 `table` (열 너비) | 합격자 부원 등록 |
| `review-list-actions` | 표 밖 아래 버튼 줄(등록하기) | 합격자 부원 등록 |
| `review-cell-chevron` | 행 끝 `>` 아이콘 칸 | 서류 평가 |
| `evaluation-underline-tabs` | 평가 화면 탭(개인 평가·운영진 평가 현황) | 지원자 평가 화면 |

### 2.3 덮어쓸 때 주의할 점

- 서류 평가 화면 CSS에는 버튼·입력칸·표를 한꺼번에 바꾸는 규칙이 있다(`.evaluation-page button`, `.evaluation-page table:has(> thead) th` 등). 새 규칙은 이보다 우선순위가 높도록 범위 클래스와 대상 클래스를 함께 쓰고, 파일 맨 아래에 둔다.
- 열 너비는 화면 코드의 `<col style={{ width }}>` 인라인 값을 덮어야 해서 `!important`를 쓴다. 다른 곳에는 `!important`를 새로 쓰지 않는다.
- 입력칸(`textarea`)은 기본값이 줄 안 배치(`inline-block`)라 아래에 글자 기준선 여백(약 6px)이 붙는다. 간격을 정확히 맞추려면 `display: block`으로 둔다.

## 3. 수치

단위 `u` = 16px. 간격은 0.5 / 0.75 / 1 / 1.5 / 2u를 기본으로 쓰고, 평가 화면 카드 안은 4절의 값을 쓴다.

### 3.1 글자

| 대상 | 값 | 실제 크기 |
| --- | --- | --- |
| 페이지 제목, 지원자 이름 | 1.5u | 24px |
| 영역 제목(지원서 답변, 개인 평가) | 1.125u | 18px |
| 표 내용·표 머리글·필터·버튼·지원자 수·입력 라벨 | 0.875u | 14px |
| 지원서 장문 답변 | 1u, 줄 높이 1.6 | 16px |
| 질문 제목 | 1u, 줄 높이 1.5 | 16px |
| 부가 설명(문항 라벨, 개인정보 항목명, 부문 태그) | 0.8125u | 13px |

제목과 표 머리글은 굵기로 구분한다. 전역 `html` 글자 크기는 바꾸지 않는다.

### 3.2 도구 줄과 버튼

| 대상 | 값 |
| --- | --- |
| 필터·정렬·검색창·새로고침·등록하기 높이 | 최소 2.5u(40px). 고정 높이 대신 `min-height`와 안쪽 여백 |
| 필터 좌우 여백 | 왼쪽 1u, 오른쪽 2.5u(화살표 자리) |
| 검색창 너비 | 15u(240px), 화면보다 넓으면 줄어듦 |
| 컨트롤 사이 간격 | 0.5u |
| 도구 줄 → 표 | 0.75u |
| 지원자 수 시작점 | 표 첫 열 글자 시작선(칸 여백 0.75u + 테두리 1px) |
| 검색·새로고침 | 한 묶음. 공간이 모자라면 묶음 전체가 다음 줄로 내려감 |

### 3.3 표

| 대상 | 값 |
| --- | --- |
| 셀 여백 | 세로 0.875u, 가로 0.75u |
| 행 안 드롭다운(최종 평가) | 최소 높이 2.25u(36px), 너비 6u |
| 서류 평가 표 열 | 이름 5.5u · 학기 4u · 졸업 예정 6u · 합격·보류·불합 각 3.75u · 총점수 4.5u · 개인 평가 6u · 최종 평가 8u · `>` 2.5u. 학교·전공이 남는 너비를 나눠 씀. 최소 너비 66u |
| 합격자 부원 등록 표 열 | 이름 5.5u · 부문 6.5u · 연락처 8.5u · 생년월일 7u. 이메일·대학교·전공이 남는 너비를 나눠 씀 |
| 전체 지원 현황 표 | 열 너비를 고정하지 않음(글자 길이에 맞춤) |

모든 열을 같은 비율로 나누지 않는다. 짧은 값(숫자·날짜) 열은 머리글과 값이 한 줄에 들어가는 만큼만 주고, 남는 너비는 글자가 긴 열에 준다. 화면이 좁으면 글자를 줄이지 않고 표 상자 안에서만 가로 스크롤한다.

## 4. 지원자 평가 화면

### 4.1 배치

| 대상 | 값 |
| --- | --- |
| 지원서 답변 : 개인 평가 | `grid-template-columns: minmax(0, 1.618fr) minmax(0, 1fr)` |
| 세로 전환 기준 | 화면 안 영역(컨테이너) 61rem(854px) 이하. 개인 평가 칸이 약 300px보다 좁아지면 점수와 평가 버튼 세 개가 한 줄에 들어가지 않기 때문 |
| 세로일 때 | 답변·평가 칸이 각자 스크롤(최대 높이 70vh) |

세로 전환은 화면 너비가 아니라 평가 화면 자체의 너비로 판단한다(`container-type: inline-size`와 `@container`). 사이드바를 접고 펴는 것에 따라 실제 남는 너비가 달라지기 때문이다.

### 4.2 카드 안 간격

| 대상 | 값 | 실제 크기 |
| --- | --- | --- |
| 카드 안쪽 여백 | 1.3125u | 21px |
| 카드 제목 → 첫 내용 | 1.3125u | 21px |
| 질문 번호 → 질문 | 0.5u | 8px |
| 질문 → 답변 | 0.8125u | 13px |
| 답변 끝 → 다음 질문 번호 | 2.125u | 34px |
| 평가 라벨 → 입력칸 | 0.5u | 8px |
| 입력칸 끝 → 다음 라벨 | 1.3125u | 21px |
| 평가 버튼 사이 | 0.5u | 8px |
| 스크롤 영역 → 저장 버튼 | 1.3125u | 21px |

간격이 두 번 더해지지 않게 하는 방법:

- 큰 덩어리 사이(카드 제목 → 내용, 스크롤 영역 → 저장 버튼)는 카드의 `gap` 하나로 띄운다. 그 자리의 제목 아래 margin과 저장 버튼 위 margin은 0으로 둔다.
- 첫 질문과 첫 라벨은 위 여백을 0으로 둔다. 그 위 간격은 카드 `gap`이 맡는다.
- 지원자가 쓴 답변의 줄바꿈은 `white-space: pre-wrap`으로 유지한다.

### 4.3 탭 위치(곡률 맞춤)

탭 줄(개인 평가·운영진 평가 현황)을 통째로 바로 아래 카드의 모서리 곡선이 끝나는 지점으로 옮긴다. 카드 둥글기가 12px(`.review-paper`, `.review-panel`의 `border-radius`)이므로 탭 줄에 좌우 바깥 여백(`margin-inline`) 12px를 두고, 안쪽 여백은 0으로 둔다.

안쪽 여백(`padding`)으로 탭만 밀면 줄 아래 회색 밑줄은 카드 끝부터 그려져서, 파란 밑줄 앞에 회색이 12px 남는다. 바깥 여백으로 줄 전체를 옮기면 첫 글자, 파란 밑줄, 회색 밑줄이 모두 같은 지점에서 시작한다.

다른 화면에서 상자 밖 글자를 상자에 맞출 때도 같은 방법을 쓴다. 기준은 바로 아래 상자의 `border-radius` 값이다. 표 상자는 `rounded-md`(6px), 평가 화면 카드는 12px다.

## 5. 다른 화면에 옮기는 순서

1. 화면 최상위 요소에 범위 클래스를 붙인다. 새 화면이 서류 평가 화면이 아니면 `evaluation-scale`을 그대로 쓰지 말고 그 화면용 범위 클래스를 새로 만들어, 1절의 `--u` 정의를 함께 둔다.
2. 2.2절 표를 보고 도구 줄·표·버튼 줄에 같은 이름의 클래스를 붙인다. 검색창과 새로고침은 `review-search-group`으로 감싼다.
3. 표 열 너비는 3.3절 방식으로 정한다. 짧은 값 열을 머리글 기준으로 먼저 정하고, 나머지를 긴 글자 열에 준다. 화면 코드에 `<col>` 너비가 있으면 범위 CSS에서 `nth-child`와 `!important`로 덮는다.
4. 카드가 있는 화면은 4.2절의 간격을 `gap` 우선으로 적용하고, 4.3절 방법으로 상자 밖 글자를 곡선 끝에 맞춘다.
5. 6절의 항목을 브라우저에서 측정한다.

## 6. 확인 방법과 결과

브라우저에서 요소의 위치(`getBoundingClientRect`)와 계산된 스타일(`getComputedStyle`)을 재서 확인한다. 눈으로 보는 것만으로는 2~6px 차이를 놓친다.

| 확인 항목 | 2026-11-21 결과 |
| --- | --- |
| 다섯 화면(분석·시각화·엔지니어링·전체 지원 현황·합격자 부원 등록) 제목 / 컨트롤 높이 / 표 글자 / 셀 여백 | 모두 24px / 40px / 14px / 14px·12px |
| 잘린 셀(말줄임 칸 제외) | 없음 |
| 1440px에서 표 가로 스크롤 | 없음 |
| 860px에서 검색·새로고침 | 같은 줄, 표는 상자 안에서만 가로 스크롤 |
| 최종 평가 드롭다운(대표진 목 계정 `boaz_president_1`) | 높이 36px, 글자 잘림 없음 |
| 평가 화면 카드 간격(4.2절 9개 항목) | 1440px와 150% 확대 모두 목표값과 같음 |
| 답변 : 개인 평가 비율 | 1.618 |
| 탭 첫 글자·파란 밑줄·회색 밑줄 시작 ↔ 카드 왼쪽 | 모두 12px(카드 둥글기와 같음) |

150% 확대는 CSS `zoom`이 아니라, 1440×900 창을 150%로 확대했을 때와 같은 조건(CSS 뷰포트 960×600, 픽셀 비율 1.5)으로 창을 열어 확인했다. 자동화 브라우저에서는 Ctrl+'+' 확대 명령을 쓸 수 없기 때문이다.

### 알려진 문제

화면 너비 1000px 이하에서는 표 상자만이 아니라 페이지 전체가 가로로 스크롤된다. 이 규칙을 적용하기 전의 분석 화면에서도 같았으므로(860px에서 문서 너비 1309px) 앱 전체 배치의 문제이고, 이 문서의 범위 밖이다.
