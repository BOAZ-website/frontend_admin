## 0. 읽는 법

**격차 유형** — `동일` `이동` `분할` `병합` `확장` `축소` `누락` `추가`

**원인** — 이 열이 이 문서에서 가장 중요하다. 원인을 구분하지 않으면 목록 전체가 고발장처럼 읽힌다.

| 원인 | 뜻 | 조치 방향 |

## 5. 설계 전제가 성립하지 않는 항목

### 5.1 라우터 부재 — 원인 하나에 결과 여섯

`ia/02-ia-tree.md` §3(라우트 맵 21개 경로)과 §4(공통 레이어)가 전제하는 것들이 **한 가지 이유로 동시에 성립하지 않는다.** 개별 결함으로 흩어 보면 여섯 건이지만 실제로는 하나다.

| 설계 의도 | 현재 |
| --- | --- |
| 지원서 딥링크 공유 (`/evaluation/board/:applicantId`) | 불가 — 평가자끼리 대상을 말로 전달해야 함 |
| 북마크 · 새로고침 후 같은 화면 복원 | 불가 — 항상 초기 화면으로 |
| 브라우저 뒤로가기 | 불가 |
| 권한 미달 경로 진입 시 403 (리다이렉트 아님) | 불가 — 경로 자체가 없음 |
| 권한별 랜딩 라우팅 | 부분 — 역할별 시작 화면은 있으나 URL이 없음 |
| 미노출 경로 직접 진입 차단 | 불가 |

**접근 제어가 2중 구조라는 점이 핵심이다.** 스펙은 "사이드바 미노출 + 경로 가드"를 함께 요구하는데, 라우터가 없으면 두 번째 층을 만들 수 없다. 권한 제어를 논의할 때 반드시 함께 다룬다. → [92 §3.1](92-open-items.md)

### 5.2 출결 상태 체계가 여러 벌로 갈라짐

| 출처 | 값 | 개수 |
| --- | --- | --- |
| 공유 타입 (출결 입력 · 대시보드 · 점수 집계) | 출석 · 지각 · 결석 | 3 |
| BASE·ADV·스터디 출결 화면 | 출석 · 지각 · 조퇴 · 결석 · 인정결석 · 비대면 · 무단지각 · 무단결석 · 미정 | 9 |
| 행사 출결 화면 | 출석 · 지각 · 조퇴 · 결석 · 인정결석 · 무단지각 · 무단결석 · 미체크 | 8 |
| 점수 규칙 화면 | 지각 · 무단지각 3회 · 조퇴 · 사유결석 · 무단결석 (감점) | 5 |

점수 규칙은 **감점 체계**, 출결 입력·집계는 **가점 체계**라 두 체계가 서로 대응되지 않는다. → [92 §3.2](92-open-items.md)

### 5.3 점수 규칙이 점수 집계에 연결되지 않음

점수 규칙 화면은 저장 시 "전체 출결 표와 시트 수식에 반영되었습니다"로 안내하지만, 출결 점수 집계 화면은 고정 배점을 사용한다. 규칙을 실제로 참조하는 화면은 BASE·ADV·스터디 출결 관리뿐이다. **안내 문구와 실제 동작이 달라 운영자가 잘못 신뢰할 수 있다.** → [92 §2.7](92-open-items.md)

### 5.4 리크루팅과 서류 평가의 지원자 데이터가 분리됨

두 영역이 각각 별도의 지원자 데이터를 기준으로 화면을 구성하고 있어, 공고·문항을 수정해도 평가 화면에 반영되지 않는다. 사전 알림 명단과 실제 지원자를 잇는 식별 키도 없다. → [92 §2.8](92-open-items.md)

### 5.5 CSV 생성 방식이 스펙과 다름

`ia/02-ia-tree.md` 3.3은 CSV 추출을 **서버가 생성해 S3에 올리는 방식**(파일 직반환 아님)으로 정의했으나, 구현은 브라우저에서 직접 생성해 내려받는다. 목업 데이터 문제와 별개로 **아키텍처가 다르므로 연동 시 로직을 다시 작성해야 한다.**

### 5.6 목록 페이징 부재

`ia/02-ia-tree.md` §4는 페이징을 공통 레이어로 정의했다(page 1부터, size 기본 6, 최대 100). 현재 모든 목록 화면이 전량 렌더하므로 지원자·명단이 늘면 성능과 가독성 문제가 발생한다.
