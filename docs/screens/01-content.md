> 이 페이지는 관리자 페이지 내 **콘텐츠 관리 영역의 현재 화면 구성과 기능을 정리한 자료**다. 콘텐츠 관리 기능은 서비스운영팀이 직접 운영하며, 웹사이트에 노출되는 주요 콘텐츠를 관리자 페이지에서 조회/등록/수정/삭제할 수 있도록 구성한다.

<!-- SYNC:common-preconditions START — 원본: docs/screens/00-common.md#공통-전제 -->

> **실제 구현은 현재 백엔드에 이미 구현되어 있는 API 명세를 기준으로 진행한다.**
> 화면에 노출하는 데이터와 등록/수정 등 사용 가능한 동작은 현재 API에서 제공하는 필드와 기능을 우선 기준으로 구성한다.

> **현재 화면은 디자인 확정본이 아니다.** 아직 별도의 UI/UX 디자인 작업은 진행하지 않았으며, PoC 수준으로 대략적인 화면 구조만 구성한 상태이다.
> 실제 디자인 단계에서는 현재 백엔드 API 명세에 맞춰 노출 필드와 등록/수정 동작, 상태 처리 등을 다시 정리하고, 운영진이 조회/등록/수정/삭제할 때 어떤 화면 구성과 작업 동선이 가장 효율적인지 검토한 뒤 최종 디자인을 진행할 예정이다.

> **현재 화면의 데이터는 화면을 벗어나면 유지되지 않는다.** 백엔드 연동 전 PoC이므로 등록·수정 결과는 새로고침 시 초기화된다.

> **현재 역할에 따른 화면 노출 제어는 적용되어 있지 않다.** 사이드바는 모든 계정에 동일한 메뉴를 노출한다. 이 문서의 권한 표기는 [`spec/02-role-model.md`](../spec/02-role-model.md)가 정의한 의도값이다.

> **현재 화면은 라우터 없이 동작한다.** 화면 전환이 컴포넌트 상태로만 이뤄지므로 개별 화면 URL·딥링크·새로고침 복원·권한 미달 시 403이 성립하지 않는다.

<!-- SYNC:common-preconditions END -->

> **현재 상태**
>
> **충족한 요구사항**
> - 아카이빙 3종(프로젝트·기술블로그·활동사진) 조회·등록·수정·삭제 및 이미지 첨부
> - FAQ 조회·등록·수정·삭제, 카테고리 분류, 노출 여부 관리
> - 수료자 후기 조회·등록·수정·삭제, 트랙 분류
> - 커리큘럼 트랙별 단계 조회·추가·삭제·순서 변경·일괄 저장
> - 등록 시 필수값 검증 및 미래 날짜 차단(아카이빙)
>
> **남은 요구사항**
> - 아카이빙 삭제 시 첨부 이미지 동시 삭제에 대한 확인 절차 강화
> - "사이트에 노출" 토글의 실제 반영 시점 정의 (저장 즉시 반영인지, 별도 배포 단계가 있는지)
> - 아카이빙 링크 필드 구성이 탭마다 다름 — API 명세와 대조 확인
> - 커리큘럼만 편집 모델이 다름 (항목 단위 저장이 아닌 트랙 전체 일괄 저장)

## 페이지별 구현 기능

### 1. 아카이빙 관리

**화면 목적:** 서비스운영팀이 웹사이트 아카이빙 영역에 노출되는 프로젝트·기술블로그·활동사진 콘텐츠를 관리하는 화면이다.

**화면 구성:** 상단 탭으로 프로젝트 / 기술블로그 / 활동사진 세 종류를 전환하고, 각 탭은 서로 다른 백엔드 엔드포인트에 대응한다. 본문은 좌측 목록과 우측 편집 패널로 나뉘어, 목록에서 항목을 선택하면 우측에서 바로 편집하는 구조다.

**가능한 기능**

- **아카이빙 목록 조회**  -  선택한 종류의 등록된 콘텐츠를 이미지·제목·기수·트랙·링크·노출 여부와 함께 확인한다.
- **아카이빙 등록**  -  새 항목을 추가하고 이미지와 링크를 함께 등록한다.
- **아카이빙 수정**  -  기존 항목의 내용과 첨부 이미지를 수정한다.
- **아카이빙 삭제**  -  노출이 필요하지 않은 항목을 삭제한다.  `안전장치 필요`
- **첨부 이미지 관리**  -  대표 이미지를 등록·교체·삭제하고 원본 크기로 확인한다.
- **콘텐츠 필터링**  -  트랙과 기수로 목록을 좁히고 제목·팀명으로 검색한다.
- **사이트 노출 여부 지정**  -  개별 항목의 웹사이트 노출을 켜고 끈다.
- **전송 데이터 확인**  -  등록·수정 시 백엔드로 전달되는 데이터를 확인한다. (개발·연동 검증용)

**입력 항목**

| 항목 | 필수 | 비고 |
| --- | :-: | --- |
| 제목 | ● | |
| 팀명 | | 프로젝트는 팀명, 기술블로그·활동사진은 작성자명 |
| 기수 | ● | 양수만 허용 |
| 날짜 | ● | **미래 날짜 지정 불가** (과거·당일만 허용) |
| 트랙 | | 분석 · 엔지니어링 · 시각화 |
| 반기 | | 활동사진 전용 (예: 21-1, 21-2) |
| 링크 | | 종류별로 다름 — 프로젝트: github·slideshare·web / 기술블로그: medium·github / 활동사진: instagram |
| 사이트에 노출 | | |

**대응 엔드포인트**

| 탭 | 엔드포인트 |
| --- | --- |
| 프로젝트 | `/api/v1/admin/archiving/projects` |
| 기술블로그 | `/api/v1/admin/archiving/blogs` |
| 활동사진 | `/api/v1/admin/archiving/activities` |

> **삭제 시 첨부 이미지가 함께 지워진다.** 현재 확인 단계가 1회뿐이고 복구 경로가 없다. IA 설계 기준([`ia/01-ia-strategy.md`](../ia/01-ia-strategy.md))은 되돌릴 수 없는 작업에 2단 확인을 요구하므로, 디자인 단계에서 확인 절차를 강화한다.

### 2. 자주 묻는 질문 (FAQ) 관리

**화면 목적:** 서비스운영팀이 웹사이트에 노출되는 FAQ 항목을 관리하는 화면이다.

**가능한 기능**

- **FAQ 목록 조회**  -  등록된 질문과 답변을 카테고리별로 확인한다. 항목을 펼쳐 답변 전문을 본다.
- **FAQ 등록**  -  새로운 질문과 답변을 추가한다.
- **FAQ 수정**  -  기존 질문 또는 답변 내용을 수정한다.
- **FAQ 삭제**  -  사용하지 않는 항목을 삭제한다.
- **노출 여부 전환**  -  항목을 웹사이트에서 숨기거나 다시 노출한다.
- **표시 순서 지정**  -  카테고리 안에서의 정렬 순서를 지정한다.
- **FAQ 검색**  -  카테고리 필터와 질문·답변 검색으로 항목을 찾는다.

**입력 항목**

| 항목 | 필수 | 비고 |
| --- | :-: | --- |
| 카테고리 | ● | 리크루팅 · 활동 안내 · 기타 |
| 정렬 순서 | | |
| 질문 | ● | |
| 답변 | ● | |
| 사이트에 노출 | | |

목록에는 최종 수정일과 우선순위가 함께 표시되고, 숨긴 항목은 별도로 구분된다.

### 3. 수료자 후기 관리

**화면 목적:** 서비스운영팀이 웹사이트에 노출되는 수료자 후기 콘텐츠를 관리하는 화면이다.

**가능한 기능**

- **수료자 후기 목록 조회**  -  등록된 후기를 작성자·기수·트랙과 함께 확인한다.
- **수료자 후기 등록**  -  신규 후기를 추가한다.
- **수료자 후기 수정**  -  기존 후기 내용을 수정한다.
- **수료자 후기 삭제**  -  노출이 필요하지 않은 후기를 삭제한다.
- **후기 검색**  -  트랙 필터와 작성자·내용 검색으로 항목을 찾는다.

**입력 항목**

| 항목 | 필수 | 비고 |
| --- | :-: | --- |
| 작성자 이름 | ● | |
| 수료 기수 | ● | |
| 트랙 | ● | 데이터 분석 · 데이터 엔지니어링 · 데이터 시각화 |
| 프로필 이미지 URL | | 미입력 시 샘플 이미지 사용 가능 |

### 4. 커리큘럼 관리

**화면 목적:** 서비스운영팀이 웹사이트에 노출되는 트랙별 커리큘럼 정보를 관리하는 화면이다.

**화면 구성:** 상단에서 트랙을 선택하면 해당 트랙의 커리큘럼 단계 전체가 편집 가능한 형태로 펼쳐진다. 다른 세 화면과 달리 항목별 등록 모달이 없고, 단계 전체를 편집한 뒤 한 번에 저장하는 구조다.

**가능한 기능**

- **커리큘럼 목록 조회**  -  선택한 트랙의 단계 구성을 순서대로 확인한다.
- **단계 추가**  -  트랙에 새 커리큘럼 단계를 추가한다.
- **단계 수정**  -  기간·제목·학습 내용·기술 스택을 편집한다.
- **단계 순서 변경**  -  단계를 위아래로 이동해 진행 순서를 조정한다.
- **단계 삭제**  -  사용하지 않는 단계를 제거한다.
- **트랙 커리큘럼 일괄 저장**  -  편집한 트랙의 단계 전체를 한 번에 저장한다.

**단계별 입력 항목**

| 항목 | 비고 |
| --- | --- |
| 기간 | 예: 1~3주차 |
| 단계 제목 | |
| 학습 내용 및 목표 | |
| 기술 스택 / 토픽 키워드 | 쉼표로 구분 |

> **저장 단위가 트랙 전체다.** 화면 안내문은 "일괄 저장 시 공식 홈페이지에 즉시 반영됩니다"로 표기되어 있으며, IA 문서([`ia/02-ia-tree.md`](../ia/02-ia-tree.md) 5.2)도 "PUT은 전체 교체 · 부분 전송 시 나머지 삭제"로 정의하고 있어 API 명세와 일치한다. 다만 같은 콘텐츠 관리 메뉴 안에서 이 화면만 저장 방식이 달라, 디자인 단계에서 저장 시점과 범위를 명확히 안내할 필요가 있다.

## 확정이 필요한 사항

| 항목 | 결정 주체 | 결정되면 바뀌는 것 |
| --- | --- | --- |
| "사이트에 노출" 토글의 반영 시점 — 저장 즉시인지, 별도 배포 단계가 있는지 | 서비스운영팀 + 백엔드 | 저장 후 안내 문구와 상태 표시 방식 |
| 아카이빙 삭제 확인 절차 — 2단 확인을 적용할지 | 서비스운영팀 | 삭제 동선과 확인 모달 구성 |
| 커리큘럼 편집 모델 — 일괄 저장을 유지할지, 다른 화면과 맞출지 | 서비스운영팀 | 커리큘럼 화면 전체 구조 |

전역·도메인 교차 사항은 [`92-open-items.md`](92-open-items.md)를 본다.
