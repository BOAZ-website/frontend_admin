> 이 페이지는 관리자 페이지 내 **서류 평가 영역의 현재 화면 구성과 기능을 정리한 자료**다. 제출된 지원서를 평가하고, 전체 지원자의 제출 상태를 확인하며, 평가 종료 후 최종 합불 및 정회원 승격까지 관리하는 흐름을 기준으로 구성한다.

<!-- SYNC:common-preconditions START — 원본: docs/screens/00-common.md#공통-전제 -->

> **실제 구현은 현재 백엔드에 이미 구현되어 있는 API 명세를 기준으로 진행한다.**
> 화면에 노출하는 데이터와 등록/수정 등 사용 가능한 동작은 현재 API에서 제공하는 필드와 기능을 우선 기준으로 구성한다.

> **현재 화면은 디자인 확정본이 아니다.** 아직 별도의 UI/UX 디자인 작업은 진행하지 않았으며, PoC 수준으로 대략적인 화면 구조만 구성한 상태이다.
> 실제 디자인 단계에서는 현재 백엔드 API 명세에 맞춰 노출 필드와 상태 처리, 평가 및 최종 합불 동작 등을 다시 정리하고, 평가자와 대표진의 실제 작업 동선을 검토한 뒤 최종 디자인을 진행할 예정이다.

> **현재 화면의 데이터는 화면을 벗어나면 유지되지 않는다.** 백엔드 연동 전 PoC이므로 등록·수정 결과는 새로고침 시 초기화된다.

> **현재 역할에 따른 화면 노출 제어는 적용되어 있지 않다.** 사이드바는 모든 계정에 동일한 메뉴를 노출한다. 이 문서의 권한 표기는 [`spec/02-role-model.md`](../spec/02-role-model.md)가 정의한 의도값이다.

> **현재 화면은 라우터 없이 동작한다.** 화면 전환이 컴포넌트 상태로만 이뤄지므로 개별 화면 URL·딥링크·새로고침 복원·권한 미달 시 403이 성립하지 않는다.

<!-- SYNC:common-preconditions END -->

> **현재 상태**
>
> **충족한 요구사항**
> - 제출 지원서 목록 조회, 트랙·최종 판정 필터, 지원자명·대학교·전공 검색
> - 평가 진행 현황 통계 (제출 건수, 내 심사 완료율, 합격·보류·불합격·미결 건수)
> - 지원자 상세 평가 — 인적사항, 지원서 원문, 테이블형 답변 표시
> - 개인 평가 입력(판정 4단계 · 1~10점 · 평가 메모 · 면접 추천 질문)과 저장
> - 저장 시 합격 수·총점 재계산 및 목록 정렬 반영
> - 동료 평가 현황 조회, 면접 추천 질문 모아보기
> - 지원자 간 이전·다음 이동
> - 최종 합격자 목록 조회 및 정회원 승격 실행 (확인 모달 2단 체크)
>
> **남은 요구사항**
> - 최종 합불 확정에 확인 단계와 변경 이력 추가
> - 최종 합불 확정 권한을 대표진(SUPER)으로 제한
> - 미제출(DRAFT) 지원자의 평가·합격 처리 차단 규칙
> - 정회원 승격 취소 경로
> - 승격 부분 실패 시 실패 명단 표시
> - 평가자 신원을 로그인 계정과 연결 (현재는 고정값)
> - 평가 이력 보존 (현재는 덮어쓰기)
> - 지원자 데이터를 리크루팅 영역과 같은 기준으로 연결
> - 지원서 전체 삭제 (시즌 종료 후 개인정보 정리 절차)

## 페이지별 구현 기능

### 1. 서류 평가 대시보드 (SUBMITTED)

**화면 목적:** 평가자가 제출된 지원서를 심사하고 대표진이 최종 합불을 확정하는 화면이다.

**화면 구성:** 상단에 평가 진행 현황을 6개 지표로 요약하고, 그 아래 필터와 검색, 본문은 지원자 목록 표로 구성된다. 목록은 합격 수 내림차순으로 정렬되어 상위 후보가 먼저 보인다. 지원자 행을 누르면 상세 평가 화면이 열린다.

**가능한 기능**

- **지원자 목록 조회**  -  제출된 지원서를 부문·대학교·전공·평가 집계와 함께 확인한다.
- **평가 진행 현황 확인**  -  제출 건수, 내 심사 완료율, 합격·보류·불합격·미결 건수를 확인한다.
- **지원자 검색·필터링**  -  트랙과 최종 판정으로 목록을 좁히고 지원자명·대학교·전공으로 검색한다.
- **서류 심사 시작**  -  지원자를 선택해 상세 평가 화면을 연다.
- **최종 합불 확정**  -  대표진이 지원자의 최종 판정(합격·보류·불합격·미결)을 확정한다.  `안전장치 필요`

**목록 표시 항목:** 지원자 성명 · 부문 · 대학교/본전공 · 졸업 예정 · 합격 수 · 보류 수 · 불합격 수 · 총점 · 내 평가 · 최종 평가

> **최종 합불 확정에 확인 절차가 없다.** 목록에서 판정을 선택하면 확인 단계 없이 즉시 확정되고, 변경 이력도 남지 않는다. 이 값이 곧 승격 대상 명단을 결정하므로, 리크루팅 운영 중 오조작이 발생하면 근거를 확인할 수 없다. **확정 절차(확인 단계 · 변경 이력 · 확정 권한 범위)를 대표진과 먼저 합의한 뒤 화면에 반영한다.**

> 설계 문서는 최종 평가 변경을 **대표진(SUPER) 전용**으로 노출하도록 정의하고 있으나, 현재는 모든 계정에 노출된다. 역할 제어 적용 시 함께 처리한다.  `IA 격차`

### 2. 전체 지원자 현황 (DRAFT 포함)

**화면 목적:** 운영진이 제출 여부와 관계없이 전체 지원 규모와 제출 진행 상태를 확인하는 화면이다.

**가능한 기능**

- **전체 지원자 목록 조회**  -  작성중(DRAFT)과 제출 완료(SUBMITTED)를 함께 확인한다.
- **제출 상태 확인**  -  지원자별 현재 제출 상태를 구분해 확인한다.
- **지원자 검색·필터링**  -  평가 대시보드와 동일한 조건으로 목록을 좁힌다.

> **평가 대시보드와 같은 화면이고 필터 조건 하나만 다르다.** 여기는 미제출 지원서까지 함께 보여준다.

> **상단 통계와 목록의 기준이 다르다.** 통계 카드는 제출분만 집계하고 목록은 미제출을 포함하므로, 같은 화면에서 두 숫자가 어긋나 보인다. 기준을 통일한다.

> **미제출(DRAFT) 지원자에게도 평가와 합불 처리가 열려 있다.** 제출하지 않은 지원서를 합격 처리하는 것을 막는 규칙이 없다. 허용 여부를 정한 뒤 화면에 반영한다.  `확정 필요`

### 3. 지원자 상세 평가

**화면 목적:** 평가자가 지원서 원문을 읽고 개인 평가를 입력하며, 동료 평가와 면접 질문을 함께 확인하는 화면이다.

**화면 구성:** 지원자 목록에서 진입하며 세 개 영역으로 나뉜다. 지원서 원문과 개인 평가 입력, 동료 평가 현황, 면접 추천 질문 모아보기다. 상단에서 지원자를 이전·다음으로 넘기며 연속으로 심사할 수 있다.

**가능한 기능**

- **지원서 원문 조회**  -  인적사항과 문항별 답변을 확인한다. 테이블형 문항은 표 형태로 표시된다.
- **개인 평가 입력**  -  판정(합격·보류·불합격·미결), 1~10점 점수, 평가 메모, 면접 추천 질문을 작성한다.
- **개인 평가 저장**  -  입력한 평가를 저장한다. 저장 즉시 집계와 목록 정렬에 반영된다.
- **동료 평가 확인**  -  다른 평가자의 판정·점수·메모를 확인한다.
- **면접 추천 질문 확인·복사**  -  평가자별로 작성된 면접 질문을 모아 보고 복사한다.
- **지원자 이동**  -  목록 순서대로 이전·다음 지원자로 넘어간다.
- **새로고침**  -  `표시만 구현`

**인적사항 표시 항목:** 성명 · 학년/학기 · 대학교 · 본전공 · 복수/부전공 · 병역 여부 · 졸업 예정 · 대학원 진학 · 연락처 · 이메일

> **평가자 신원이 고정값이다.** 로그인 계정과 평가자가 연결되어 있지 않아 "내 평가"가 실제 사용자 기준으로 동작하지 않는다. 인증 연동 시 함께 처리한다.

> **개인 평가는 덮어쓰기 방식이라 이전 점수·메모가 남지 않는다.** 평가 근거를 소명해야 하는 상황에 대응할 수 없으므로, 이력 보존 여부를 확정한다.  `확정 필요`

### 4. 최종 합불 및 정회원 승격

**화면 목적:** 대표진이 서류 평가 이후 최종 합격자를 확인하고 정회원으로 승격 처리하는 화면이다.

**화면 구성:** 상단에 최종 합격자 수·승격 대기 인원·승격 완료 인원을 요약하고, 본문은 합격자 목록 표다. 승격할 대상을 선택한 뒤 실행하면 확인 모달에서 대상 명단과 처리 내용을 다시 확인하고 체크 두 개를 거쳐 실행한다.

**가능한 기능**

- **최종 합격자 목록 조회**  -  최종 판정이 합격인 지원자를 계정 상태·승격 여부와 함께 확인한다.
- **승격 대상 선택**  -  개별 선택하거나 미승격 합격자를 전체 선택한다.
- **정회원 승격 실행**  -  선택한 합격자를 정회원(MEMBER)으로 전환한다.  `안전장치 필요`
- **승격 현황 확인**  -  승격 완료·대기 인원을 구분해 확인한다.

**목록 표시 항목:** User ID · 지원자 성명 · 합격 부문 · 이메일(계정 ID) · 연락처 · 대학교/본전공 · 계정 상태 및 권한 · 승격 상태

승격 시 서버가 각 지원자의 최신 제출 지원서에서 이름·전화번호·대학교·전공을 회원 정보로 복사하고 회원 유형을 정회원으로 변경한다. 개별 트랜잭션으로 처리되어 부분 성공을 허용한다.

> **이 시스템에서 가장 되돌리기 어려운 작업이다.** 승격되면 목록에서 선택이 비활성화되고 **승격을 취소하는 경로가 화면에 없다.** 현재 방어책은 확인 모달의 체크박스 두 개뿐이다. 오처리 시 대응 절차를 백엔드와 함께 확정한다.

> **부분 실패 결과를 볼 수 없다.** 백엔드가 부분 성공을 허용하는데 실패 명단을 표시하는 화면이 없어, 일부만 승격된 경우 대상을 확인할 수 없다.

> 설계 문서는 이 화면을 **결과 처리** 단계로 정의하고 `CSV 추출 → 합격자 승격 → 지원서 전체 삭제`를 한 화면에 순서대로 두도록 했다. 현재는 CSV 추출이 리크루팅 영역으로 분리되어 있고 지원서 전체 삭제는 구현되어 있지 않다.  `IA 격차`

## 확정이 필요한 사항

| 항목 | 결정 주체 | 결정되면 바뀌는 것 |
| --- | --- | --- |
| 최종 합불 확정 절차 — 확인 단계·변경 이력·확정 권한 범위 | 대표진 | 평가 목록의 확정 동선, 이력 화면 신설 여부 |
| 정회원 승격 취소 정책 — 화면에서 되돌릴 수 있게 할지, 백엔드 수동 대응으로 둘지 | 대표진 + 백엔드 | 승격 화면의 방어 수준과 확인 단계 수 |
| 미제출(DRAFT) 지원자의 평가·합격 처리 허용 여부 | 대표진 | 평가 대상 필터 규칙 |
| 평가 이력 보존 여부 | 대표진 | 개인 평가 저장 방식, 이력 조회 화면 |
