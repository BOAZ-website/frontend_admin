> 이 페이지는 관리자 페이지 내 **리크루팅 공고 관리 영역의 현재 기능과 화면 구조를 정리한 자료**다. 모집 공고 등록부터 지원서 문항 설정, 지원자 데이터 확인 및 추출까지 리크루팅 운영에 필요한 기능을 관리자 페이지에서 관리하는 것을 목적으로 한다.

<!-- SYNC:common-preconditions START — 원본: docs/screens/00-common.md#공통-전제 -->

> **실제 구현은 현재 백엔드에 이미 구현되어 있는 API 명세를 기준으로 진행한다.**
> 화면에 노출하는 데이터와 등록/수정 등 사용 가능한 동작은 현재 API에서 제공하는 필드와 기능을 우선 기준으로 구성한다.

> **현재 화면은 디자인 확정본이 아니다.** 아직 별도의 UI/UX 디자인 작업은 진행하지 않았으며, PoC 수준으로 대략적인 화면 구조만 구성한 상태이다.
> 실제 디자인 단계에서는 현재 백엔드 API 명세에 맞춰 노출 필드와 등록/수정 동작, 상태 처리 등을 다시 정리하고, 운영진이 조회/등록/수정/삭제할 때 어떤 화면 구성과 작업 동선이 가장 효율적인지 검토한 뒤 최종 디자인을 진행할 예정이다.

> **현재 화면의 데이터는 화면을 벗어나면 유지되지 않는다.** 백엔드 연동 전 PoC이므로 등록·수정 결과는 새로고침 시 초기화된다.

> **현재 역할에 따른 화면 노출 제어는 적용되어 있지 않다.** 사이드바는 모든 계정에 동일한 메뉴를 노출한다. 이 문서의 권한 표기는 [`spec/02-role-model.md`](../spec/02-role-model.md)가 정의한 의도값이다.

> **현재 화면은 라우터 없이 동작한다.** 화면 전환이 컴포넌트 상태로만 이뤄지므로 개별 화면 URL·딥링크·새로고침 복원·권한 미달 시 403이 성립하지 않는다.

<!-- SYNC:common-preconditions END -->

> **현재 상태**
>
> **충족한 요구사항**
> - 모집 공고 조회·등록·수정·삭제 및 접수 기간 기준 상태 자동 계산
> - 지원서 문항 조회·등록·수정·삭제, 트랙별 분류, 순서 변경
> - 문항 유형 3종(장문형·단문형·테이블형) 및 테이블형 행·열 구조 편집
> - 답변이 등록된 문항의 삭제 차단
> - 지원자 화면 미리보기 (트랙별 전환, 문항 수정 즉시 반영)
> - 트랙별 지원서 CSV 다운로드 및 엑셀 한글 호환 처리
> - 사전 알림 명단 조회·등록·삭제, 알림 문구 템플릿 관리
>
> **남은 요구사항**
> - 전형별 상세 일정 편집 기능 (표시는 되나 수정 수단이 없음)
> - 지원자 화면 미리보기의 제출 동작 정의 — 참고 화면인지 실제 제출 경로인지
> - CSV 추출을 실제 지원자 데이터와 연결 (현재는 고정 예시 데이터)
> - CSV 추출 조건(기수·합불) 선택 기능
> - 사전 알림 명단과 실제 지원자 간 연결 기준
> - 사전 알림 발송 방식 확정 — 수동 복사 유지인지 카카오/SMS 연동인지

## 페이지별 구현 기능

### 1. 모집 공고 관리

**화면 목적:** 서비스운영팀이 기수별 신입 부원 모집 공고를 등록하고 접수 기간을 관리하는 화면이다.

**가능한 기능**

- **모집 공고 목록 조회**  -  등록된 공고를 기수·상태·접수 기간과 함께 확인한다.
- **모집 공고 등록**  -  새 기수의 공고를 만들고 접수 기간과 홍보 책자를 지정한다.
- **모집 공고 수정**  -  기존 공고의 기수·기간·홍보 책자·활성화 여부를 변경한다.
- **모집 공고 삭제**  -  등록된 공고를 제거한다.  `안전장치 필요`
- **홍보 책자 확인**  -  등록된 홍보 책자 PDF를 새 창에서 연다.
- **지원 현황 요약 확인**  -  해당 기수의 작성중(DRAFT)·제출 완료(SUBMITTED) 건수와 홍보 책자 등록 여부를 확인한다.

**입력 항목**

| 항목 | 비고 |
| --- | --- |
| 모집 기수 | |
| 접수 시작일 | |
| 접수 마감일 | |
| 홍보 책자 PDF URL | S3 경로 |
| 공고 활성화 | |

**모집 상태**는 현재 시각과 접수 기간을 기준으로 자동 계산된다 (모집 예정 / 모집 진행중 / 모집 마감). 별도로 마감 처리하는 동작은 없다.

> **전형별 상세 일정은 목록 카드에 표시되지만 편집 수단이 없다.** 공고 등록 시 서류 접수·1차 서류 발표 2단계가 고정으로 생성되고 이후 변경할 수 없다. 실제 전형 단계는 기수마다 달라지므로 편집 기능이 필요하다.  `확정 필요`

> IA 문서([`ia/02-ia-tree.md`](../ia/02-ia-tree.md) 4.1)는 **지원자나 문항이 존재하는 공고는 삭제를 차단**하도록 정의하고 있다(`RECRUITMENT_HAS_REFERENCES`). 현재 화면은 확인 1회 후 바로 삭제되므로 연동 시 차단 규칙을 함께 적용한다.

### 2. 지원서 문항 설정

**화면 목적:** 서비스운영팀이 지원자가 작성할 지원서 문항을 트랙별로 구성하는 화면이다.

**화면 구성:** 상단 카테고리 필터로 공통 문항과 트랙별 문항을 나눠 보고, 본문은 문항 카드 목록으로 구성된다. 문항 추가·수정은 별도 모달에서 진행하며, 테이블형 문항은 모달 안에서 행·열 구조를 만들고 실시간 미리보기로 확인한다.

**가능한 기능**

- **문항 목록 조회**  -  등록된 문항을 카테고리·유형·필수 여부와 함께 순서대로 확인한다.
- **문항 등록**  -  선택한 카테고리에 새 문항을 추가한다.
- **문항 수정**  -  문항 내용·유형·글자수 제한·필수 여부를 변경한다.
- **문항 삭제**  -  사용하지 않는 문항을 제거한다. 답변이 등록된 문항은 삭제되지 않는다.
- **문항 순서 변경**  -  같은 카테고리 안에서 문항을 위아래로 이동한다.
- **테이블형 문항 구조 편집**  -  열 헤더와 행 항목을 추가·삭제해 표 형태의 응답 양식을 만든다.

**입력 항목**

| 항목 | 필수 | 비고 |
| --- | :-: | --- |
| 트랙 구분 | | 공통 · 데이터 분석 · 데이터 엔지니어링 · 데이터 시각화 |
| 문항 라벨 | | 관리자 화면 표기명 |
| 문항 내용 | ● | 지원자에게 보이는 질문 |
| 문항 보조 설명 | | |
| 문항 유형 | | 장문형 · 단문형 · 테이블형 |
| 글자수 제한 | | 테이블형이 아닐 때만 |
| 다중 행 작성 허용 | | 테이블형일 때만 |
| 열 헤더 목록 / 행 항목 목록 | | 테이블형일 때만 |
| 필수 응답 여부 | | |

> **답변이 있는 문항은 삭제가 차단된다.** 이 도메인에서 데이터 보호 규칙이 적용된 유일한 지점이다.

> **문항 보조 설명은 입력은 받지만 어디에도 표시되지 않는다.** 문항 카드에도, 지원자 화면 미리보기에도 렌더되지 않는다. 사용할 항목이면 노출 위치를 정하고, 아니면 입력 필드를 제거한다.  `확정 필요`

### 3. 지원자 화면 미리보기

**화면 목적:** 서비스운영팀이 설정한 문항이 지원자에게 어떻게 보이는지 관리자 페이지에서 확인하기 위한 참고 화면이다.

**가능한 기능**

- **트랙별 지원서 미리보기**  -  분석 · 엔지니어링 · 시각화 트랙의 지원서 화면을 각각 확인한다. 공통 문항이 먼저, 선택한 트랙 문항이 뒤에 표시된다.
- **문항 변경 즉시 확인**  -  문항 설정에서 수정한 내용이 미리보기에 바로 반영된다.
- **임시 저장 (DRAFT)**  -  `표시만 구현`
- **지원서 최종 제출 (SUBMITTED)**  -  `표시만 구현`

> **이 화면의 목적을 먼저 확정해야 한다.** 현재 두 제출 버튼은 화면에 배치되어 있으나 동작하지 않고, 입력란도 값이 저장되지 않는 확인용이다. 이 화면이 **운영진 확인용 참고 화면인지, 실제 지원자 제출 경로인지**에 따라 처리 방향이 달라지므로, 목적을 확정한 뒤 동작을 연결하거나 버튼을 제거한다.
>
> 해당 기능의 실제 필요 여부는 서비스운영팀 내부 논의 후 결정하며, 운영상 필요하지 않다고 판단될 경우 화면을 제거할 수 있다.  `확정 필요`

### 4. 지원서 CSV 추출

**화면 목적:** 서비스운영팀이 모집 기간 동안 접수된 지원자 데이터를 평가 및 운영에 활용할 수 있도록 CSV로 추출하는 화면이다.

**가능한 기능**

- **트랙별 CSV 다운로드**  -  분석 · 엔지니어링 · 시각화 트랙의 지원서를 트랙 단위로 내려받는다.  `임시 데이터`
- **트랙별 지원 현황 확인**  -  트랙별 지원자 수를 확인한다.

**추출 항목**

고정 항목 15개에 문항 라벨이 이어 붙는 구조다.

| 구분 | 항목 |
| --- | --- |
| 고정 (15) | 지원자 식별자 · 지원 트랙 · 이름 · 이메일 · 전화번호 · 1차 합불결과 · 대학교 · 전공 · 복수전공 · 재학 학기 · 병역 · 생년월일 · 졸업예정연월 · 향후계획 · 제출일시 |
| 동적 | 공통 문항 라벨 → 해당 트랙 문항 라벨 (설정한 순서대로) |

파일명은 `applicants_{트랙}_{결과}_{날짜}.csv` 형식이며, 엑셀에서 한글이 깨지지 않도록 처리되어 있다.

> **현재 추출되는 데이터는 실제 지원자가 아니라 고정 예시다.** 헤더는 설정한 문항에서 실시간으로 생성되지만 데이터 행은 고정값이라, 화면에 표시된 지원자 수와 실제 추출 행 수가 일치하지 않는다. 실제 구현 단계에서 **백엔드 지원자 API를 단일 기준으로 삼아 연결**한다.

> **추출 조건 선택 기능이 없다.** 기수와 합불 조건이 고정되어 있어 특정 기수나 합격자만 추출할 수 없다. 추출 API 파라미터와 화면 필터를 함께 확정한다.  `확정 필요`

> IA 문서([`ia/02-ia-tree.md`](../ia/02-ia-tree.md) 3.3)는 CSV 추출을 **서류 평가의 "결과 처리" 단계**에 두고 `CSV 추출 → 합격자 승격 → 지원서 전체 삭제` 순서를 강제하도록 설계했다. 현재 구현은 CSV 추출만 리크루팅 영역에 분리되어 있다. → [`92-open-items.md`](92-open-items.md)

### 5. 사전 알림 명단

**화면 목적:** 서비스운영팀이 리크루팅 시작 전 사전 알림을 신청한 명단을 확인하고 안내 문구를 발송하는 화면이다.

**화면 구성:** 좌측은 알림 문구 템플릿 편집 영역, 우측은 선택한 수신자 기준 미리보기이며, 하단에 신청자 명단 표가 배치된다. 명단에서 수신자를 선택하면 우측 미리보기가 해당 수신자 기준으로 바뀐다.

**가능한 기능**

- **사전 알림 명단 조회**  -  신청자를 관심 트랙·연락처·신청 일시·발송 상태와 함께 확인한다.
- **신청자 직접 등록**  -  명단에 신청자를 수동으로 추가한다.  `API 근거 없음`
- **신청 내역 삭제**  -  개별 신청 내역을 제거한다.  `API 근거 없음`
- **알림 문구 템플릿 편집**  -  발송할 안내 문구를 작성하고 기본 양식으로 저장한다.
- **개인화 문구 복사**  -  수신자 이름·기수·트랙·모집 기간이 치환된 문구를 클립보드로 복사한다.
- **발송 상태 관리**  -  개별 또는 일괄로 발송 완료 여부를 표시한다.  `안전장치 필요`
- **명단 검색·필터링**  -  이름·연락처·이메일 검색과 발송 상태·트랙 필터로 대상을 좁힌다.

**템플릿 치환 변수:** `{name}` `{term}` `{track}` `{start_date}` `{end_date}` — 활성 공고를 기준으로 치환된다.

> **실제 발송 연동은 없다.** 현재는 문구를 복사해 운영진이 직접 발송하는 방식이며, 발송 여부도 사람이 표시한다. 카카오/SMS 연동 여부를 확정해야 발송 상태 관리 화면의 설계가 정해진다.  `확정 필요`

> **일부 기능이 현재 API 명세를 넘어선다.** IA 문서([`ia/02-ia-tree.md`](../ia/02-ia-tree.md) 4.3)는 이 화면을 "목록 추출 → 대표진 전달 → 전체 삭제"로 정의하고 **개별 삭제 API가 없다**고 명시하고 있다. 현재 구현된 개별 등록·개별 삭제·발송 상태 토글은 백엔드 연동 시점에 동작하지 않으므로, **기능을 유지할지(백엔드 신규 요청) 정리할지** 먼저 결정한다.  `API 근거 없음`

> **필터를 적용한 상태에서 전체 선택 시 화면에 보이지 않는 대상까지 선택된다.** 일괄 발송 완료 처리는 확인 단계 없이 즉시 실행되고, 되돌리려면 건별로 수동 복구해야 한다.  `안전장치 필요`
