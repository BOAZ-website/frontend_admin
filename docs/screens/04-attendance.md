> 이 페이지는 관리자 페이지 내 **출결 및 점수 관리 영역의 현재 화면 구성과 기능을 정리한 자료**다. 정규 활동(BASE·ADV)과 스터디, 행사의 출결을 조회·입력·집계하고, 출결 기반 활동 점수를 산출하는 흐름을 기준으로 구성한다.
>
> 이 영역은 **유일하게 백엔드가 신규로 구축되는 도메인**이며, 설계 스펙은 [`spec/01-attendance-system.md`](../spec/01-attendance-system.md)에 있다.

> **실제 구현은 현재 백엔드에 이미 구현되어 있는 API 명세를 기준으로 진행한다.**
> 화면에 노출하는 데이터와 등록/수정 등 사용 가능한 동작은 현재 API에서 제공하는 필드와 기능을 우선 기준으로 구성한다.

> **현재 화면은 디자인 확정본이 아니다.** 아직 별도의 UI/UX 디자인 작업은 진행하지 않았으며, PoC 수준으로 대략적인 화면 구조만 구성한 상태이다.
> 실제 디자인 단계에서는 백엔드 API 명세에 맞춰 노출 필드와 상태 처리를 다시 정리하고, 운영지원팀과 스터디장의 실제 작업 동선을 검토한 뒤 최종 디자인을 진행할 예정이다.

> **현재 화면의 데이터는 화면을 벗어나면 유지되지 않는다.** 백엔드 연동 전 PoC이므로 등록·수정 결과는 새로고침 시 초기화된다. 점수 규칙(`boaz_score_rules`)·스터디장 안내문 양식(`boaz_delivery_template`)·사전 알림 문구 양식(`boaz_custom_notify_template`) 세 가지만 브라우저(localStorage)에 저장된다.

> **현재 역할에 따른 화면 노출 제어는 적용되어 있지 않다.** 사이드바는 모든 계정에 동일한 메뉴를 노출한다. 이 문서의 권한 표기는 [`spec/02-role-model.md`](../spec/02-role-model.md)가 정의한 의도값이다.

> **현재 화면은 라우터 없이 동작한다.** 화면 전환이 컴포넌트 상태로만 이뤄지므로 개별 화면 URL·딥링크·새로고침 복원·권한 미달 시 403이 성립하지 않는다.

> - 리더의 출결 수정 요청 → 운영지원팀 승인·거절 큐
> - 출결 대시보드 주차별 제출 매트릭스 및 인증 사진 대조 검토
> - HOST 계정 발급·재발급·회수, 스터디장 안내문 템플릿 관리
> - 점수 규칙 조회·수정, 버전(DRAFT/ACTIVE/INACTIVE) 관리
>
> **남은 요구사항**
> - 인증 사진 확인 / 반려 / 재제출 Flow (현재는 확인 완료 처리만 있고 반려 경로가 없음)
> - 확인 완료 여부를 출결 대시보드 매트릭스에 표시
> - 점수 규칙을 점수 집계에 반영 (현재 규칙을 바꿔도 집계는 고정 배점 사용)
> - 5주차 이후 출결 저장
> - 정규 출결 회차 생성 진입점
> - ADV 팀장용 입력 화면의 분리 여부 확정
> - ADV 팀별 비대면 횟수 자동 카운트
> - BASE 병행 인원 자동 포함
> - 예외 승인 거절 시 사유 기록
> - 운영지원팀 수정 시 리더 작성 사유 보존
> - 출결 상태 값 체계 통일 (현재 화면마다 다름)
> - 활동·주차·팀 편성 (주차 일정 등록, 팀원 배정)

## 페이지별 구현 기능

### 1. BASE Term 출결 관리

**화면 목적:** 운영지원팀이 분석·시각화·엔지니어링 3개 트랙의 BASE 세션 출결을 조회하고 직접 입력하는 화면이다.

**화면 구성:** 상단에서 방학/학기 구간과 주차를 선택하고, 좌측 목록에서 트랙을 고르면 우측에 해당 트랙의 출결 표가 열린다. 전체 주차를 선택하면 회원별 행과 주차별 열이 이어지는 누적 그리드가, 특정 주차를 선택하면 그 주차의 명단이 표시된다.

**가능한 기능**

- **전체 출결 조회**  -  방학 또는 학기 구간의 주차별 출결을 한 화면에서 확인한다.
- **주차별 출결 조회**  -  특정 주차의 트랙별 출결 명단을 확인한다.
- **출결 직접 입력**  -  회원별 출결 상태를 지정하고 비고를 작성한다.
- **명단 CSV 업로드**  -  외부 명단 파일로 출결 데이터를 일괄 반영한다.  `안전장치 필요`
- **출결 CSV 추출**  -  주차별 날짜를 매핑하고 열 순서를 지정해 내려받는다.
- **명단에서 제외**  -  대상이 아닌 인원을 명단에서 제거한다.

> **CSV 업로드가 기존 명단을 전체 교체한다.** 부분 반영 수단이 없어, 일부만 수정할 의도로 업로드하면 기존 데이터가 사라진다. 업로드 전 미리보기와 확인 단계가 필요하다.

> **화면에 표시되는 출결 코드와 CSV 추출 코드 체계가 다르다.** 예를 들어 출석이 화면에서는 `0`, CSV에서는 `1`로 기록된다. 코드 체계를 통일한다.

### 2. ADV Term 출결 관리

**화면 목적:** 운영지원팀이 산학 연계·실무 프로젝트 ADV 팀별 출결을 조회하고 관리하는 화면이다.

**화면 구성:** BASE 출결과 같은 구조이며, 좌측 목록이 트랙이 아니라 트랙별로 묶인 프로젝트 팀이다. 전체를 선택하면 ADV 인원 전체의 통합 출결이, 개별 팀을 선택하면 해당 팀의 상세 출결이 열린다.

**가능한 기능**

- **ADV 전체 통합 출결 조회**  -  ADV 인원의 주차별 출결을 통합해 확인한다.
- **팀별 출결 조회**  -  특정 팀의 주차별 출결과 마일스톤 참여 현황을 확인한다.
- **출결 직접 입력**  -  초기 주차에 운영지원팀이 직접 출결을 입력한다.
- **출결 수정**  -  팀에서 제출된 출결을 운영지원팀이 수정한다.
- **비대면 참여 기록**  -  비대면으로 참여한 회차를 별도 상태로 기록한다.
- **출결 CSV 추출**  -  비대면 횟수를 포함한 집계표를 내려받는다.

> **비대면 횟수 자동 카운트가 없다.** 상태로는 기록되지만 팀별 누적 횟수를 자동으로 세어 보여주지 않는다.

> **직접 입력이 가능한 구간이 제한되어 있다.** 방학 1~3주차에만 캡슐형 버튼으로 바로 입력할 수 있고, 그 외 구간은 수정 모드로 전환해야 한다. 구간 기준을 운영 실태에 맞춰 재확인한다.  `확정 필요`

### 3. 스터디 출결 관리

**화면 목적:** 운영지원팀이 A~D팀 스터디의 회차별 출결과 인증 내역을 확인하고 점수를 집계하는 화면이다.

**화면 구성:** 좌측에서 전체 스터디 또는 개별 팀을 선택한다. 전체를 선택하면 회원별로 각 스터디 팀의 누적 점수와 총점이 나란히 보이고, 개별 팀을 선택하면 그 팀 구성원의 회차별 출결과 참여 횟수, 스터디장 여부, 최종 점수가 보인다.

**가능한 기능**

- **전체 스터디 출결 현황 조회**  -  등록된 스터디별 제출·진행 상태를 한눈에 확인한다.
- **개별 스터디 출결 조회**  -  구성원별 회차 출결과 날짜, 참여 횟수, 점수를 확인한다.
- **출결 수정**  -  제출된 출결을 운영지원팀이 수정한다.
- **전체 점수 집계 CSV 추출**  -  회원별 스터디 점수와 총합을 내려받는다.
- **개별 스터디 CSV 추출**  -  구성원별 회차 출결 상세와 점수 산출 결과를 내려받는다.

> **정렬 기준을 전환할 수 있다.** 전체 스터디 뷰에서 기수별과 팀별 정렬을 바꿔 볼 수 있다.

### 4. 행사 출결 관리

**화면 목적:** 운영지원팀이 컨퍼런스·해커톤 등 행사의 참가자 명단을 등록하고 현장에서 출결을 체크하는 화면이다.

**화면 구성:** 행사 목록에서 행사를 선택하면 해당 행사의 출석부로 이동한다. 출석부는 상단 요약 통계와 필터, 참가자 표로 구성되며 표의 컬럼은 행사마다 다르게 설정할 수 있다.

**가능한 기능**

- **행사 목록 조회**  -  등록된 행사를 날짜·장소와 함께 확인한다.
- **행사 생성**  -  새 행사의 기본 정보와 출석 명단 컬럼을 설정한다.
- **행사 기본 정보 수정**  -  행사명·일자·장소를 변경한다.
- **행사 삭제**  -  행사와 해당 출석 명단을 함께 제거한다.  `안전장치 필요`
- **출석 명단 표 컬럼 설정**  -  행사 특성에 맞는 수집 항목을 추가하고 순서를 조정한다.  `API 근거 없음`
- **CSV 명단 일괄 등록**  -  외부에서 전달받은 참가자 명단을 파일로 등록한다.
- **현장 참가자 추가**  -  사전 명단에 없던 참석자를 현장에서 개별 추가한다.
- **현장 출결 체크**  -  참가자별 출결 상태를 지정한다. 키보드 숫자키와 방향키로 연속 체크할 수 있다.
- **명단·비고 수정**  -  등록된 참가자 정보와 운영상 특이사항을 정정한다.
- **출석부 CSV 다운로드**  -  행사 출결 결과를 내려받는다.
- **출석 양식 템플릿 관리**  -  `진입 경로 미구현` `API 근거 없음`
- **출석 통계 및 리포트**  -  `진입 경로 미구현`

**출결 상태:** 출석 · 지각 · 조퇴 · 결석 · 인정결석 · 무단지각 · 무단결석 · 미체크

> **CSV 일괄 등록 방식을 정리할 예정이다.** 현재는 파일 업로드·엑셀 붙여넣기·부원 불러오기 세 가지를 제공하지만, **CSV 파일 업로드만 남기는 방향**으로 검토 중이다. 부원 불러오기는 확인 단계 없이 클릭 즉시 명단에 추가된다.  `확정 필요`

> **키보드로 이동한 현재 행에 시각적 표시가 없다.** 단축키로 연속 체크할 때 지금 누구를 체크하고 있는지 화면에서 확인할 수 없다.

> **행사별 동적 컬럼을 저장할 스키마가 스펙에 없다.** 기능을 유지하려면 백엔드 신규 요청이 필요하다.  `API 근거 없음`

### 5. 출결 점수 집계

**화면 목적:** 운영지원팀이 스터디 출결을 기반으로 자동 산출된 활동 점수를 확인하는 화면이다.

**가능한 기능**

- **스터디별 점수 집계 조회**  -  회원별 주차 점수와 합계를 합계 내림차순으로 확인한다.
- **시즌·스터디 선택**  -  방학/학기 구간과 대상 스터디를 전환한다.

읽기 전용 화면이며 입력이나 수정 동작은 없다. 미제출 회차는 값 대신 `—`로 표시된다.

> **점수 규칙을 바꿔도 이 화면은 변하지 않는다.** 배점(출석 +1 / 지각 +0.5 / 결석 0)이 화면에 고정되어 있어 점수 규칙 화면의 설정을 참조하지 않는다. 점수 규칙 화면은 저장 시 "전체 출결 표와 시트 수식에 반영되었습니다"로 안내하므로, **운영자가 반영되었다고 잘못 신뢰할 수 있다.** 연결 여부를 확정한다.  `확정 필요`

> **내보내기 기능이 없다.** 집계 결과를 파일로 받을 수단이 이 화면에는 없다.

### 6. 리더 전용 출결 입력 (팀장용)

**화면 목적:** 스터디장과 ADV 팀장이 본인이 담당하는 팀의 출결을 직접 입력하고 인증 사진과 함께 제출하는 화면이다.

**화면 구성:** 일반 운영진 화면과 분리된 리더 전용 화면이다. 상단에서 담당 스터디와 주차를 선택하고, 인증 사진을 첨부한 뒤 구성원별 출결을 체크한다. 우측에 해당 주차의 제출 요약이 함께 표시된다.

**가능한 기능**

- **담당 스터디·주차 선택**  -  입력할 대상과 주차를 고른다. 담당 스터디는 로그인 계정에 따라 고정된다.
- **출석 인증 사진 첨부**  -  출결 증빙 사진을 등록하고 교체·삭제한다.
- **스터디원 추가**  -  명단에 없는 구성원을 추가한다. 여러 명을 한 번에 입력할 수 있다.
- **구성원별 출결 입력**  -  출석·지각·결석을 지정하고 사유를 작성한다. 사유는 선택 입력이다.
- **명단에서 삭제**  -  대상이 아닌 구성원을 제거한다.
- **출결 및 사진 제출**  -  해당 주차의 출결을 최종 제출한다.
- **운영지원팀에 수정 요청**  -  제출 후 수정이 필요한 항목을 사유와 함께 요청한다.

제출 후에는 리더가 직접 수정할 수 없고, 수정 요청은 출결 대시보드의 승인 대기 큐로 전달된다. 이는 설계 스펙([`spec/01-attendance-system.md`](../spec/01-attendance-system.md) §3-3)의 "제출 전에는 자유롭게, 제출 후에는 요청으로" 원칙과 일치한다.

> **5주차 이후는 제출해도 데이터가 저장되지 않는다.** 화면에서는 8주차까지 선택할 수 있으나 5주차 이상은 제출해도 반영되지 않고 안내도 표시되지 않는다. **입력자가 제출 완료로 인지하게 되어 출결 누락으로 이어지므로, 실제 운영 투입 전 반드시 처리한다.**

> **메뉴 라벨과 실제 화면이 다르다.** 사이드바의 "ADV 입력 및 증빙 (팀장용)"과 "스터디 입력 및 증빙 (팀장용)"이 **같은 화면을 연다.** ADV 전용 입력 화면은 현재 없다. 아래 「확정이 필요한 사항」에서 다룬다.  `IA 격차`

> **리더가 직접 회차를 생성할 수 없다.** 설계 스펙의 매주 동선은 "로그인 → 주차 선택 → 세션 생성 → 명단 확인 → 제출"인데, 회차를 생성하는 경로가 화면에 없어 운영지원팀이 미리 만들어둔 주차에만 입력할 수 있다.  `진입 경로 미구현`

### 7. HOST 계정·팀 연결 (ID/PW 발급)

**화면 목적:** 운영지원팀이 스터디를 등록하고 담당 리더에게 발급할 HOST 계정을 만들어 전달하는 화면이다.

**화면 구성:** 상단에 발급 절차 4단계를 안내하고, 본문은 등록된 스터디와 연결된 계정 목록 표다. 스터디를 등록하면 계정이 자동 발급되고, 곧바로 전달용 안내문 양식이 열린다.

**가능한 기능**

- **스터디 등록 및 계정 발급**  -  스터디를 만들고 담당 리더의 로그인 계정을 함께 발급한다.
- **계정 목록 조회**  -  스터디별 로그인 아이디·초기 비밀번호·계정 상태를 확인한다.
- **비밀번호 확인**  -  가려진 초기 비밀번호를 확인한다.
- **비밀번호 재발급**  -  새 임시 비밀번호를 생성한다.
- **계정 회수·활성화**  -  기수 종료 시 계정을 잠그거나 다시 활성화한다.
- **안내문 복사**  -  접속 정보가 채워진 전달용 안내문을 복사한다.
- **안내문 양식 관리**  -  전달 문구 양식을 편집하고 기본 양식으로 저장한다.

발급 절차는 화면에 4단계로 안내된다 — ① 스터디 등록 → ② HOST 계정 자동 발급 → ③ 출결 탭·대시보드 연동 → ④ 스터디장에게 정보 전달.

> **계정이 함께 생성되지 않은 스터디는 관리 동작이 반응하지 않는다.** 목록이 스터디 기준으로 표시되기 때문에, 연결된 계정이 없는 스터디에서 회수·활성화·재발급을 눌러도 아무 일이 일어나지 않는다. 운영자가 처리된 것으로 오인할 수 있다.

> **초기 비밀번호가 항상 같은 값으로 생성된다.** 자동 생성 버튼이 고정값을 채우므로 발급 정책을 확정해야 한다.  `확정 필요`

> **안내문 양식이 브라우저에만 저장된다.** 담당자가 바뀌거나 기기가 달라지면 사라진다. 저장 위치를 서버로 옮길지 결정한다.  `API 근거 없음`

### 8. 점수 규칙

**화면 목적:** 대표진이 출결 상태별 점수 배점 규칙을 정하고 버전을 확정하는 화면이다.

**화면 구성:** 정규 활동과 스터디 두 영역으로 나뉘어 각각 산출 수식과 항목별 배점 표를 보여준다. 하단에 규칙 버전 목록이 있어 새 초안을 작성하고 활성화할 수 있다.

**가능한 기능**

- **점수 규칙 조회**  -  정규 활동과 스터디의 항목별 배점을 확인한다.
- **배점 수정**  -  활성 규칙의 수치를 변경하고 저장한다.
- **신규 초안(DRAFT) 작성**  -  새 버전의 규칙 초안을 만든다.
- **규칙 버전 활성화**  -  초안을 활성 규칙으로 확정한다. 기존 활성 규칙은 자동으로 비활성이 된다.
- **버전 이력 조회**  -  버전별 상태·활성일·작성자와 주요 배점 요약을 확인한다.

**정규 활동 항목:** 지각 · 무단지각 3회 · 조퇴 · 사유결석 · 무단결석(3회 시 제명) · 운영진 인정 사유결석
**스터디 항목:** 미이수 · 출석률 70% 미만 · 100% 출석 · 70~100% 출석 · 스터디장 가산점

> **이전 버전으로 되돌릴 수 없다.** 비활성 버전에는 활성화 수단이 없어 롤백이 불가능하다.

> **"미이수"와 "출석률 70% 미만" 두 항목이 같은 값을 공유한다.** 한쪽을 바꾸면 다른 쪽도 함께 바뀐다. 두 항목을 분리할지 확정한다.  `확정 필요`

> **규칙 항목 체계와 실제 출결 상태 체계가 대응되지 않는다.** 규칙은 감점 5분류인데 출결 입력과 집계는 가점 3분류다. 통일 기준을 확정한다.  `확정 필요`

> **규칙 초안 작성과 확정을 같은 사람이 연달아 할 수 있다.** 스펙은 `RULE_EDIT`(작성)와 `RULE_ACTIVATE`(확정)를 별도 권한으로 정의하고 있다. 분리 여부는 [`spec/02-role-model.md`](../spec/02-role-model.md) §3.3에서 다룬다.

### 9. 출결 대시보드 및 인증 검토

**화면 목적:** 운영지원팀이 스터디별 제출 현황을 한눈에 보고, 제출된 인증 사진과 출결 사유를 대조 검토하는 화면이다.

**화면 구성:** 상단에 시즌 진행 단계와 제출률·미제출·승인 대기 건수를 요약하고, 본문은 주차 × 스터디 제출 매트릭스다. 셀을 누르면 해당 회차의 인증 사진과 구성원별 출결 상세가 열린다. 하단에 예외 승인 대기 큐가 있다.

**가능한 기능**

- **제출 현황 매트릭스 조회**  -  주차별·스터디별 제출 상태를 격자로 확인한다.
- **인증 사진 대조 검토**  -  제출된 인증 사진을 원본 크기로 확인하고 출결 내역과 대조한다.
- **운영지원팀 출결 수동 수정**  -  제출된 출결을 사유와 함께 정정한다. 사유는 필수다.
- **출결 확인 완료 처리**  -  검토를 마친 회차를 확인 완료로 표시한다.
- **예외 승인**  -  리더가 요청한 출결 수정을 승인해 실제 출결에 반영한다.
- **예외 거절**  -  요청을 반려한다.
- **시즌 전환**  -  방학 스터디와 학기 스터디 구간을 전환한다.

> **이 화면은 사이드바 메뉴에 없다.** 운영지원팀 계정으로 로그인하거나 역할을 전환할 때만 도달한다. IA상 진입 경로를 확정한다.  `확정 필요`

> **확인 완료 여부가 매트릭스에 표시되지 않는다.** 검토를 마쳐도 셀에 표시가 남지 않아 확인·미확인을 구분할 수 없고, 같은 회차를 중복 검토하거나 누락하게 된다.

> **거절 시 사유와 이력이 남지 않는다.** 요청이 큐에서 사라지기만 해서 왜 거절되었는지 사후에 확인할 수 없다.

> **운영지원팀이 수정하면 리더가 작성한 원래 사유가 덮어써진다.** 원본 근거가 소실되어 소명이 어려워진다.

> **"이번 주 미제출" 집계가 3주차로 고정되어 있다.** 실제 진행 주차와 무관하게 계산된다.
