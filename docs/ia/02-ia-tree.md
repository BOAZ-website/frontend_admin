## 0. 설계 원칙

| 원칙 | 내용 |
| --- | --- |
| 권한이 곧 정보구조 | 사이드바 항목 자체가 권한(`role` + `teamName` + `track`)에 따라 **렌더링되지 않는다**. 비활성화(disabled)가 아니라 미노출. |
| 업무 단위로 묶는다 | 도메인(백엔드 패키지) 기준이 아니라 **운영진이 실제로 하는 일** 기준으로 묶는다. (예: 승격·CSV·지원서삭제는 `user`/`recruitment` 도메인이지만 "서류평가 → 결과 처리" 한 화면에 모은다) |
| 시즌 흐름을 순서대로 | 리크루팅은 `공고 → 질문 → 평가 → CSV → 승격 → 삭제` 순서가 어긋나면 복구 불가다. 메뉴 순서 = 실행 순서. |
| 파괴적 작업은 깊게 | 되돌릴 수 없는 액션(지원서 전체 삭제, 아카이빙 삭제)은 L3 이하로 내리고 확인 모달을 거친다. |
| 신규는 출석뿐 | 출석 외 모든 화면은 **기존 API 연동**이다. 신규 백엔드는 `attendance` 도메인 하나. |

**깊이 표기**
`L0` 진입/인증 · `L1` 사이드바 메뉴 · `L2` 페이지/탭 · `L3` 액션·모달·사이드패널

## 1. 전체 IA 트리

```
[L0] 진입
 └── 로그인 (POST /api/v1/auth/admin/login)
      └── 권한 판정 (role · teamName · track) ── 토큰 갱신/로그아웃
           └── 권한별 랜딩 라우팅
                ├── 운영지원팀      → /attendance
                ├── 대표진·차기대표진·부문 운영진 → /evaluation
                ├── 서비스운영팀    → /contents
                └── 그 외           → /dashboard

[L1] ① 대시보드                                        (전원)
      ├── [L2] 내 역할 카드 (기수 · 부문 · 팀 · 권한)
      ├── [L2] 내 할 일 (권한별 위젯)
      │         ├── 이번 주차 출석 미제출 팀       (운영지원팀 / HOST)
      │         ├── 내 평가 진행률 n/N             (평가자)
      │         └── 모집 진행 상태 · D-Day         (서비스운영팀)
      └── [L2] 내부 공지사항                        [신규·P2]

[L1] ② 출석 관리                    (운영지원팀 · HOST)   ★ 신규 백엔드
      ├── [L2] 2.1 출석 현황            (운영지원팀 통합 뷰)
      │         ├── [L3] 주차 탭 (1주차 · 2주차 … N주차)
      │         ├── [L3] 활동 그룹 (스터디 / 소모임 / 친해지기바라 / 기타)
      │         ├── [L3] 팀 카드 → 제출 상태 · 네이버카페 인증 링크
      │         ├── [L3] 미제출 팀 필터 · 팀/활동 검색
      │         └── [L3] 주차 마감 처리
      ├── [L2] 2.2 출석 입력               (HOST 전용)
      │         ├── [L3] 내 팀 · 주차 선택
      │         ├── [L3] 스프레드시트형 그리드 (행=팀원, 열=주차 · 셀=출석상태)  ※ "엑셀처럼 입력"
      │         ├── [L3] 네이버카페 인증 링크 입력          ※ 1안(카페 유지) 채택
      │         └── [L3] 임시저장 / 제출
      ├── [L2] 2.3 점수 집계               (운영지원팀)
      │         ├── [L3] 개인별 누적 점수 · 팀별 집계
      │         ├── [L3] 배점 규칙 설정 (지각/결석/사유결석 가중치)
      │         └── [L3] CSV 내보내기
      ├── [L2] 2.4 HOST 지정               (운영지원팀)
      │         ├── [L3] 팀별 HOST 목록
      │         └── [L3] HOST 부여 / 회수
      └── [L2] 2.5 활동·주차·팀 편성        (운영지원팀)   [추가 제안]
                ├── [L3] 활동 등록 (스터디/소모임/…)
                ├── [L3] 주차 일정 등록 (회차 · 날짜)

      │         ├── [L3] 내 평가 조회·저장(upsert) GET/PUT .../evaluations/me
      │         └── [L3] 최종 평가 변경            PATCH .../final-decision   ※ role=SUPER 에만 노출
      └── [L2] 3.3 결과 처리                              ※ 반드시 이 순서
                ├── [L3] ① CSV 추출     POST   /admin/recruitment/applications/download  (S3 업로드, 파일 직반환 아님)
                ├── [L3] ② 합격자 승격  PATCH  /admin/users/promote        (failed_user_ids 표 · 실패건만 재시도)

[L1] ④ 리크루팅 시즌                    (서비스운영팀)
      ├── [L2] 4.1 공고 관리
      │         ├── [L3] 목록 GET /admin/recruitment (term 내림차순)
      │         ├── [L3] 등록 POST   — term 중복 불가 · brochureUrl은 후속 수정으로 등록

      ├── [L2] 4.2 지원서 질문 관리

      └── [L2] 4.3 사전 알림 구독자
                └── [L3] 목록 추출 → 대표진 전달 → 전체 삭제 (개별 삭제 API 없음 · 버튼 하나로 묶기)

[L1] ⑤ 콘텐츠 관리                      (서비스운영팀)
      ├── [L2] 5.1 아카이빙
      │         ├── [L3] 프로젝트   (썸네일·기수·부문·제목·팀명·slideshare·컨퍼런스일)
      │         ├── [L3] 활동 사진  (대표이미지·기수·부문·반기 NN-1/NN-2·제목·인스타 링크)
      │         ├── [L3] 기술 블로그 (썸네일·기수·부문·제목·medium 링크)
      │         └── [L3] 공통: multipart(≤5MB, jpg/jpeg/png/webp) · links JSON URL 검증 · 삭제 시 S3 동시삭제 확인모달
      ├── [L2] 5.2 커리큘럼
      │         └── [L3] 트랙별 단계 전체 편집 → 일괄 저장 (PUT은 전체 교체 · 부분 전송 시 나머지 삭제)
      ├── [L2] 5.3 FAQ
      │         └── [L3] 카테고리별(RECRUITMENT/ACTIVITY/ETC) · 드래그 순서변경(임시번호 스와프)
      └── [L2] 5.4 수료자 후기
                └── [L3] track·term 필터 · 등록 전 동일 이름/기수 중복 경고 · 삭제 전 원문 표시

[L1] ⑥ 회원 · 권한 관리                 (서비스운영팀)
      ├── [L2] 6.1 관리자 계정
      │         ├── [L3] 목록/상세 GET /admin/accounts
      │         ├── [L3] 생성 POST · 평가자 계정 **일괄 생성** 흐름 (서류평가 전)
      │         ├── [L3] 수정 PATCH (role · track · term · teamName)
      │         ├── [L3] 비밀번호 초기화 PATCH .../password
      │         └── [L3] 삭제 DELETE (soft delete)
      ├── [L2] 6.2 회원(User) 관리
      │         └── [L3] 승격 결과 확인 · 기수/부문 조회 (승격 실행은 3.3에서)
      └── [L2] 6.3 내 계정  GET /admin/accounts/me · 비밀번호 변경

[L1] ⑦ 설정                              (전원 / 일부 SUPER)
      ├── [L2] 7.1 내부 공지사항 관리          [신규·P2]
      ├── [L2] 7.2 인프라 모니터링             [P2 · 알람시스템 산출물]
```

## 4. 공통 레이어 (모든 화면 관통)

공식 사이트의 "워크 스루"에 대응하는, 관리자 페이지의 횡단 관심사다. IA 노드는 아니지만 **모든 L2가 의존**한다.

- **인증**: JWT 로그인 / refresh / logout. 사이드바는 토큰의 `role·teamName·track`으로 렌더링.
- **라우팅 가드**: 미노출 경로 직접 진입 시 403 페이지 (랜딩으로 리다이렉트 X — 권한 문제임을 명시)
- **에러 코드 → 한글 메시지 매핑**: `RECRUITMENT_CLOSED`, `QUESTION_HAS_ANSWERS`, `UNSUPPORTED_ARCHIVE_CATEGORY`, `RECRUITMENT_HAS_REFERENCES`, `INVALID_TRACK_SELECTION` 등 전수
- **페이징**: page 1부터 · size 기본 6 · 최대 100
- **multipart 업로드**: 아카이빙 · 후기 이미지 공용 컴포넌트
- **파괴적 액션 모달**: 대상 id·제목 표시 + 2단 확인 (아카이빙 삭제, 지원서 전체 삭제)

## 5. 공식 웹사이트 IA와의 대비

| | 공식 웹사이트 (`www`) | 관리자 페이지 (`admin`) |
| --- | --- | --- |
| 진입 | 유입 → 워크 스루 | 로그인 → 권한 판정 |
| 탐색 축 | 콘텐츠 주제 (홈/커리큘럼/리크루팅/아카이빙/FAQ) | 업무 역할 (출석/평가/시즌/콘텐츠/권한) |
| 네비게이션 | 상단 GNB, 전원 동일 | 좌측 사이드바, **권한별 상이** |
| 깊이 | 3단 (탭 → 섹션 → 링크) | 4단 (메뉴 → 페이지 → 탭 → 액션/모달) |
| 상태 | 읽기 전용 | CUD 중심, 되돌릴 수 없는 작업 다수 |
| 관계 | — | `admin`의 ⑤ 콘텐츠 관리가 `www`의 커리큘럼·아카이빙·FAQ·후기를 **공급** |

## 6. IA 확정 전 결정해야 할 것

출석 도메인은 스펙 미확정 상태라, 아래가 정해지지 않으면 ② 출석 관리의 L2/L3가 바뀐다.

| # | 결정 사항 | IA에 미치는 영향 | 제안 |
| --- | --- | --- | --- |
| 1 | **HOST의 계정 모델** — HOST(스터디장)는 `Admin` 계정인가 `User`(MEMBER)인가? | 관리자 앱 로그인 주체가 달라짐. `User`라면 `/attendance/entry`만 별도 인증 경로가 필요해 IA가 둘로 쪼개짐 | `Admin.Role`에 `HOST` 추가 + `teamName` 미지정. ⑥ 권한 관리의 **일괄 생성 흐름을 그대로 재사용** (평가자 계정 생성과 동일 패턴) |
| 2 | 출석 단위 — 주차 × 활동 × 팀 × 개인 중 어디까지 키로 | 2.2 그리드의 행/열 구조가 결정됨 | 개인까지 (행=팀원, 열=주차) — 목업/점수집계가 개인 단위를 전제 |
| 3 | 출석 상태 enum | 2.2 셀 입력 UI, 2.3 배점 규칙 | 출석/지각/결석/사유결석 4종 |
| 4 | 카페 링크 검증 범위 | 2.1·2.2에 검증 실패 상태 노출 여부 | 형식(URL + 카페 도메인)만. 실제 접근 확인은 네이버 로그인 이슈로 불가 |
| 5 | 출석 대상자 특정 방법 | 2.5 팀원 배정 UI의 소스 | `User`(memberType=MEMBER) 중 `term` + `track` 필터 → 팀 배정 |

> 그 외: 목업 사이드바의 **공지사항**은 백엔드가 없다. P2로 두거나 IA에서 제거할지 결정 필요.
> `prod`는 `ddl-auto: validate`이므로 출석 테이블 추가 시 **DDL 수동 선적용** 후 배포할 것.
