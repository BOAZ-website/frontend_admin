## 이 문서의 규칙

- [`01-wbs.md`](01-wbs.md)에서 **FE 담당 기능 ID만** 뽑아 정리한 문서다. 담당이 `FE`이거나 `FE + BE`인 기능 ID의 FE 몫만 다룬다. BE 전용 기능 ID는 각 티켓의 "제외(BE 몫)"에 이름만 남긴다.
- **티켓 1개 = GitHub 이슈 1개 = 노션 티켓 1개.** 티켓 키는 통합 WBS와 같은 키를 쓴다(예: `REC-POST`). BE 저장소 이슈도 같은 키를 쓰면 한 티켓의 FE·BE 진행을 함께 볼 수 있다.
- GitHub 이슈 제목: `[Feat] <티켓 키> <티켓 이름>` (예: `[Feat] REC-POST 모집 공고 관리`). 이슈 본문 첫 섹션에 노션 티켓 링크를 적는다.
- 커밋·PR은 이슈 하나만 참조한다. 여러 티켓을 한 PR에 섞지 않는다.
- 각 티켓은 Why(왜 하는가) / What(무엇을 만드는가) / Acceptance(완료 조건) 순서로 쓴다.
- 디자인 확정 티켓(`*-DSN`, 담당 디자인 + PM)과 BE·인프라 전용 티켓(`SYS-AUTH`, `ATT-CORE`, `ATT-API`)은 이 문서에서 제외한다. FE 티켓의 선행 칸에만 등장한다.

# Epic 0 · 플랫폼 기반

모든 화면이 목업에서 실제 API로 넘어가려면 먼저 있어야 하는 공통 기반이다. 화면이 아니므로 기능 ID 대신 티켓 단위로 완료를 판정한다. 마일스톤 M0(2026-11-02 확정): 로그인·새로고침 복원 통과 + 화면 하나(FAQ)가 배포 환경에서 실데이터로 왕복.

### PLT-DEPLOY 프론트 CD 파이프라인

- 규모 `한 주` · 담당 FE + 인프라 · 현재 상태: 없음 (`.github/workflows/`에 검사용 워크플로만 있음) · 기존 이슈 #28
- **Why:** 2026-12 관리자 페이지 오픈 전에 운영 도메인에 빌드를 올릴 방법이 없다.
- **What:** `dev` → `main` 머지 시 빌드 → S3 업로드 → CloudFront 캐시 무효화 워크플로. 이전 커밋 재배포로 롤백.
- **제외:** AWS 배포 역할 권한 추가, CloudFront 보안 헤더·SPA 설정 (product-infra에서 진행, 이 티켓의 선행)
- **Acceptance:**
  - [ ] `main` 머지 시 배포 워크플로가 성공하고 관리자 도메인에 새 빌드가 보인다
  - [ ] `index.html` 응답이 캐시되지 않는다(no-cache)
  - [ ] 수동 실행으로 이전 커밋을 다시 배포할 수 있다
  - [ ] `production` 환경 승인 없이는 배포가 진행되지 않는다

### PLT-ROUTER 라우터 도입 + 무상태 화면 이관

- 규모 `한 주` · 담당 FE · 현재 상태: 없음 (`src/app/App.tsx`의 `ActivePage` 상태 + 주소 해시로 화면 전환)
- **Why:** 주소로 화면에 직접 들어갈 수 없고, 권한 가드(SYS-GATE)와 403 화면을 붙일 자리가 없다.
- **What:** 라우터 라이브러리를 도입하고 상태를 들고 있지 않은 화면부터 경로 기반으로 옮긴다.
- **Acceptance:**
  - [ ] 각 화면이 고유 경로를 갖고, 주소를 직접 입력해 진입할 수 있다
  - [ ] 새로고침 시 같은 화면이 유지된다
  - [ ] 사이드바·breadcrumb이 경로 기준으로 동작한다

# Epic 3 · 출결 관리

이 프로젝트에서 백엔드가 새로 만들어지는 유일한 영역이다. FE 화면은 대부분 **임시 API 단계까지 와 있고(#18, #30)**, BE(ATT-CORE · ATT-API)가 준비되면 실제 API로 바꾼다. 그래서 출결 티켓의 완료 조건은 "임시 API 단계"와 "실제 API 연동"을 나눠 체크한다.

마일스톤 M4(2027-01-04 전): 명단 등록 · 그룹 편성 + 리더 매주 입력·컨펌. M5(2027-01 중순): 운영지원팀 직접 기록 + 종합 조회 + 집계·export.

권장 순서: `ATT-ROSTER`(ROS-01·02) → `ATT-GROUP` → `ATT-ROSTER`(ROS-03) → `SET-RULE`(RULE-01·02) → `ATT-LDR` · `ATT-ADV` · `ATT-STD` → M5 티켓

### ATT-ROSTER 명단 관리 (SOT)

- 규모 `2~3주` · 현재 상태: 임시 API (`src/pages/member-management/ui/MemberManagementPage.tsx`) · 기존 이슈 #30(닫힘)
- **선행:** ATT-CORE · API-01(BE) · PLT-FORM · PLT-QUERY
- **Why:** 모든 출결 화면의 명단이 여기서 나온다. Epic 3 전체의 선행이다.
- **What:** FE 기능 ID (모두 FE + BE의 FE 몫)
  - ROS-01 명단 조회 — 기수·부문·그룹 필터, 이름 검색
  - ROS-02 회원 등록 — 개별 + CSV 일괄
  - ROS-03 속성 편집 — 멘멘·일반 스터디·팀·병행·비고 (GRP-02·03 이후)
  - ROS-04 행사별 참여 상태 — 기록 있는 인원 불참 전환 시 확인 모달

  - [ ] 실제 API로 명단을 등록·수정하고 다른 출결 화면에 바로 반영된다
  - [ ] CSV 일괄 등록에서 오류 행이 있으면 아무 행도 저장되지 않는다

# Epic 4 · 시스템·계정

권한 재설계(SYS-AUTH, BE 전담)를 전제로 계정·권한 화면을 만든다. 화면 재구현은 **SYS-DSN 이후** 시작한다(SYS-GATE 제외). 마일스톤 M2: SYS-GATE. M6(2027-01 말): 권한 전 구간. SYS-LOG 본체는 M7 이후 별도 착수.

### SYS-GATE permission 기반 게이팅

- 규모 `한 주` · 담당 FE · 현재 상태: 없음 (역할은 로그인 후 진입 화면에만 쓰이고, 사이드바는 모든 메뉴를 보여 줌)
- **선행:** PLT-SESSION(`/me` permission 목록) · PLT-ROUTER · SYS-AUTH 0~3단계(BE)
- **Why:** 운영진마다 볼 수 있는 메뉴와 누를 수 있는 버튼이 달라야 한다. M2 완료 정의에 포함된다.
- **What:** `/me` permission 목록만으로 판정(하드코딩 없음). 사이드바 미노출, 경로 가드 + 403 화면, 화면 내 버튼 게이팅, HOST는 출결 경로만. PoC 제거: 역할 전환 토글 · 빠른 로그인 · 하드코딩 비밀번호.
- **Acceptance:**
  - [ ] 권한 없는 메뉴가 사이드바에 보이지 않는다
  - [ ] 권한 없는 경로에 주소로 들어가면 403 화면이 보인다
  - [ ] HOST 계정은 출결 경로만 들어갈 수 있다
  - [ ] PoC 로그인 기능이 사라진다

### SYS-ACC 운영진 계정 관리

- 규모 `한 주` · 현재 상태: 목업 (`src/pages/system-accounts/ui/SystemAccountsPage.tsx`의 `INITIAL_ACCOUNTS`) · 기존 이슈 #38 분할
- **선행:** SYS-DSN · SYS-AUTH · PLT-CONFIRM · PLT-ERRMSG. 확인 필요: SYS-API-1
- **Why:** 운영진 계정 발급·수정·삭제를 DB 직접 수정 없이 화면에서 한다.
- **What:** FE 기능 ID: ACC-01 계정 조회·지표·필터 · ACC-02 역할·권한 확인 · ACC-03 계정 발급 · ACC-04 계정 수정 — 오버라이드 삭제 경고, 본인 변경 차단 · ACC-05 비밀번호 변경 · ACC-06 계정 삭제 — 마지막 보유자 차단, 확인 모달
- **제외(BE 몫):** `updateAccount` 강등 경로의 락아웃 검사
- **Acceptance:**
  - [ ] 실제 API로 계정 발급·수정·삭제·비밀번호 변경이 된다
  - [ ] 마지막 계정 관리 권한 보유자 삭제가 사유와 함께 막힌다
  - [ ] 역할·부서 변경 시 권한 예외 삭제 경고가 뜬다

### SYS-PERM 계정별 권한 관리

- 규모 `한 주` · 현재 상태: 목업 (같은 파일의 권한 하위 탭) · 기존 이슈 #38 분할

- **What:** FE 기능 ID: PERM-01 서버 permission 목록으로 41개 체크박스·7묶음 렌더 · PERM-02 기본 세트 체크·변경 항목 강조 · PERM-03 담당 그룹 권한 읽기 전용 · PERM-04 최종 집합 저장 · PERM-05 자기 회수·마지막 보유자 회수 거부 사유 표시
- **Acceptance:**
  - [ ] 체크박스 목록이 코드 하드코딩이 아니라 서버 응답에서 만들어진다
  - [ ] 저장 후 해당 계정 재로그인 시 메뉴가 바뀐다
  - [ ] 거부된 변경은 사유가 표시된다

### SYS-MEM 회원(User) 관리

- **What:** FE 기능 ID: MEM-01 회원 목록·필터 · MEM-02 승격 결과(일시·처리자·출신 기수) · MEM-03 회원 상세 → ATT-TL 연결

> 현재 동아리원 관리 화면(#30)이 출결 명단과 회원 관리를 한 화면으로 쓰고 있다. ATT-ROSTER와 SYS-MEM으로 나눌지 SYS-DSN에서 정한다.
