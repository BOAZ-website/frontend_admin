## 1. 문서 목적과 범위

운영지원팀의 출결·점수 관리 업무를 서비스화하기 위한 기능 명세다.

### 1.1 포함

- 세션(BASE·ADV) · 행사 · 스터디의 출결 기록
- 출결 기반 점수 자동 집계
- 명단(회원 마스터) 관리 — 인적사항 · 속성 · 참여 상태
- 스터디·팀 관리 — 생성, 장 지정, 계정 발급
- 인증 제출·컨펌 — (스터디·팀)장 제출과 운영지원팀 확인·반려
- CSV — 명단 import 1종, 최종 집계 export 3종

### 1.2 제외 (기존 방식 유지)

출결 점수 이외의 사항은 시스템 밖에서 관리한다.

- 과제 미제출 감점
- 개인 활동 가점 (외부행사 · 홍보글 · 수상 등)
- 운영진 점수
- 병행 Term 판정 (+10 / −10 / −20)
- 친친 점수
- 커트라인 판정 (제명 · 수료 등)
- 외부인 참여 행사 출결
- 인정결석 심의 절차

> **판정·처분은 사람이 한다.** 시스템은 수치 집계·표시까지만 담당하고, 제명·수료·징계·비대면 초과 판단은 운영지원팀 몫이다.

### 1.3 사용 맥락

- BASE 세션 · 행사 — 운영지원팀이 **현장에서 직접 실시간 입력**
- 스터디 · ADV 팀 — **장이 인증 제출**, 운영지원팀이 컨펌 (6.1절)

## 3. 공통 규칙

### 3.1 기수 · Term 구조

- 리크루팅은 6월·12월, **6개월 단위로 기수 부여**
- 기수 라이프사이클 — BASE Term 이수 → ADV Term → 두 Term 모두 이수 시 수료
- 한 Term의 구성 — BASE 기수(신입) · ADV 기수 · 수료 기수
    - **수료 기수는 출결·점수 규정 미적용, 명단 미등록**
- Term 구성 — **방학 최대 7주 + 학기 최대 15주** (회칙 1장 3조 · 3장 1조)
- 부문 — 분석 / 시각화 / 엔지니어링

**무효 주차**

- Term 설정(`SET-RULE`)에서 지정하며, 해당 주차는 **모든 활동의 출결 대상에서 일괄 제외**
- 용도: 중간·기말 시험기간 등 매 Term 달라지는 휴식 기간
- 스터디도 무효 주차에는 진행·인증 의무가 없다

### 3.2 출결 상태값 · CSV 코드

| 상태 | CSV 코드 | 점수 | 판정 기준 |
| --- | --- | --- | --- |
| 출석 | `1` | 0 | 정상 참여 |
| 지각 | `2` | −1 | 시작 후 15분 이내 입실 |
| 조퇴 | `3` | −1 | 시작 1시간 이후 ~ 종료 전 퇴실 |
| 사유결석 | `4` | −3 | 사전 연락한 결석 |
| 인정결석 | `5` | 0 | 심의 결과 인정된 결석 |
| 비대면 | `6` | 0 | 비대면 참여 (ADV 세션 한정) |
| 무단지각 | `O` | −1 | 사전 연락 없는 지각 |
| 무단결석 | `X` | −4 | 사전 연락 없는 결석 |
| 미기록 | **빈 칸** | — | 기록 없음, 계산 제외 |

- 숫자 계열은 정상 출결, **`O` · `X`는 무단 계열**로 구분한다. 기존 운영지원팀 집계 시트 체계를 그대로 따른다.
- **미기록은 빈 칸**으로 출력한다. `-` · `—` 같은 기호는 엑셀에서 텍스트로 잡혀 계산식에 걸린다.
- 화면에서는 사람이 읽는 상태명으로 표시하고, CSV 추출 시에만 코드로 변환한다.
- **인정결석 입력** — 심의는 오프라인에서 진행하고, 시스템에는 상태 변경과 비고 사유 기입만 한다. 증빙 파일 첨부 기능은 두지 않는다.

**활동별 사용 상태값**

| 활동 | 상태값 |
| --- | --- |
| BASE 세션 | 출석 · 지각 · 조퇴 · 사유결석 · 인정결석 · 무단지각 · 무단결석 · 미기록 |
| 행사 | 위와 동일. 단 신입 특칙형 · 1·2차 체크형은 전용 세트 (4.5절) |
| **ADV 세션** | **출석 · 결석 · 비대면 · 미기록** — 프로젝트 팀 회의라 지각·조퇴 개념이 없다. **결석은 사유결석(−3)** 으로 처리하며 무단 구분을 두지 않는다 |
| 스터디 | 출석 · 결석 · 미기록 — 사유결석 불허, 지각은 출석 처리 (회칙 8장 3조) |

### 3.3 명단 컬럼

| 컬럼 | 형식 | 비고 |
| --- | --- | --- |
| 기수 / 부문 / 이름 | 기본 3컬럼 | CSV import 대상 (7.1절) |
| 멘멘스터디 | 참여 여부 | |
| 일반 스터디 | select 참조 | `ATT-GROUP` 등록분, 복수 가능 |
| 스터디장 여부 | 파생 표시 (read-only) | `ATT-GROUP` 장 지정 기반 자동 표시, 명단에서 편집 불가 |
| 팀 | select 참조 | ADV 인원만 값 보유 |
| 병행 | select (값은 부문) | 기본 빈 값 |
| 행사별 참여 상태 | 필참 / 참여 / 불참 / 미정(—) | 행사 등록 시 컬럼 자동 추가, 초기값은 4.5절 |
| 비고 | 텍스트 | 병행 포기 등 특이사항 |
| 임의 컬럼 | 자유 추가 | `ATT-ROSTER` · `ATT-VIEW` 두 화면만 허용 |

### 3.4 설계 원칙

| 원칙 | 내용 |
| --- | --- |
| **SOT와 파생 뷰** | `ATT-ROSTER`가 SOT. 각 출결 페이지의 명단은 **조회 시점 계산**이며 스냅샷 복사를 하지 않는다. 명단 수정이 즉시 모든 파생 페이지에 반영되므로 별도 동기화 로직이 불필요하다 |
| **기록 원본 보존** | 환산·판정은 집계 레이어에서 계산한다 (대표 사례: 무단지각 환산 5.2절) |
| **변경 로그** | 마스터 데이터(명단·참여 상태) 변경 이력을 기록한다 — 누가 · 언제 · 무엇을 |
| **명시 규칙만 적용** | 회칙·규칙표에 정의된 감점·가점만 계산하고, 규정 없는 케이스는 0으로 둔다. 일반 규정은 전체 적용, 특칙(신입 OT·컨퍼런스)이 오버라이드한다 |

### 3.5 권한

| 주체 | 기본 세트 키 | 출결 관련 권한 |
| --- | --- | --- |
| 운영지원팀 | `(TEAM, 운영지원팀)` | 출결 관리·입력 전체, `HOST_ACCOUNT_*`, `SCORE_RULE_*` |
| 서비스운영팀장 | `(MASTER, 서비스운영팀)` | 위와 동일 |
| ADV 팀장 / 스터디장 | `(HOST, 그룹리더)` + 담당 그룹 | `ATTENDANCE_{ADV,STUDY}_ENTRY_OWN_GROUP_{READ,WRITE}` — **담당 그룹만, 주차 안(월~일 24:00)에만 수정, 삭제 불가** |

- HOST의 `_OWN_GROUP_` 권한은 담당 그룹 테이블에서 매 요청 계산된다. ADV·스터디 겸임 시 둘 다 붙는다.
- 주차 마감 기준은 회칙 8장 2조 3항(인증 사진 월~일 내 제출)과 일치한다.

## 4. 화면별 기능 명세

### 4.1 명단 관리 `ATT-ROSTER`

**화면 목적**: 회원 마스터(SOT). 인적사항 · 그룹 배정 · 행사별 참여 상태를 관리한다. 모든 출결 화면의 명단이 여기서 파생된다.

| ID | 기능 | 설명 |
| --- | --- | --- |
| ROS-01 | 명단 조회 | 기수 · 부문 · 그룹 필터, 이름 검색 |
| ROS-02 | 회원 등록 | 개별 등록 및 CSV 일괄 등록 (7.1절) |
| ROS-03 | 속성 편집 | 멘멘스터디 · 일반 스터디 · 팀 · 병행 · 비고 (3.3절) |
| ROS-04 | 참여 상태 관리 | 행사별 필참 / 참여 / 불참 / 미정 지정 |
| ROS-05 | 임의 컬럼 추가 | 운영상 필요한 컬럼 자유 추가 |
| ROS-06 | 변경 이력 조회 | 누가 · 언제 · 무엇을 바꿨는지 |

- 스터디·팀은 `ATT-GROUP` 등록분을 **select로 참조**하며, 이 화면에서는 배정만 한다.
- **스터디장 여부는 read-only 파생 표시**다. 장 지정은 `ATT-GROUP`에서 한다.
- 변경 정책은 6.2절.

---

### 4.2 명단 출결 `ATT-VIEW`

**화면 목적**: 전 인원의 출결을 한 화면에서 종합 조회한다. **수정 불가**이며, 기록 수정은 각 출결 화면에서만 가능하다.

| ID | 기능 | 설명 |
| --- | --- | --- |
| VIEW-01 | 종합 조회 | 전 인원 × 활동별 출결 현황 |
| VIEW-02 | 필터 | 기수 · 부문 · 활동 · 그룹 |
| VIEW-03 | 임의 컬럼 표시 | `ATT-ROSTER`에서 추가한 컬럼 반영 |

---

### 4.3 BASE 세션 출결 `ATT-BASE`

**화면 목적**: BASE 세션 출결을 주차 그리드로 기록한다. 운영지원팀이 현장에서 직접 입력한다.

| ID | 기능 | 설명 |
| --- | --- | --- |
| BASE-01 | 주차 그리드 조회 | 회원 × 주차. 방학 최대 7주 / 학기 최대 15주 |
| BASE-02 | 출결 입력 | 상태 선택 + 비고 |
| BASE-03 | 병행 인원 자동 포함 | 해당 부문을 병행으로 지정한 인원을 자동 포함 |
| BASE-04 | 무효 주차 제외 | `SET-RULE` 지정 주차는 대상에서 제외 |

**대상 산정**: BASE 기수 전원 + 해당 부문 병행 지정 인원

- 병행 인원은 **참여 상태 개념 없이 자동 포함**되며, 행에 "병행" 표시가 붙는다.
- 감점은 일반 회원과 동일하게 적용한다 (회칙 9장 1조 9항).
- 병행 Term 판정 점수(+10 / −10 / −20)는 **시스템 밖**이다 (1.2절).

---

### 4.4 ADV 세션 출결 `ATT-ADV`

**화면 목적**: ADV 팀별 출결을 주차 그리드로 확인하고, 팀장이 제출한 인증을 컨펌한다.

| ID | 기능 | 설명 |
| --- | --- | --- |
| ADV-01 | 부문·팀별 그리드 조회 | 팀 컬럼 기준으로 부문·팀별 표시 |
| ADV-02 | 인증 컨펌 | 제출 건 확인 / 반려 (6.1절) |
| ADV-03 | 직접 정정 | 컨펌 이후에도 운영지원팀이 직접 수정 |
| ADV-04 | 비대면 횟수 표시 | 각 팀 헤더에 `비대면 n회` |
| ADV-05 | 미진행 주차 표시 | 기록·제출이 없는 주차의 빈 상태 |

**주차 기준**: 팀별 회의 요일이 달라도 **주(월~일) 1회 운영**이며, 기록은 주차 기준이다.

**비대면 처리** (회칙 3장 1조 9항)

| 규칙 | 내용 |
| --- | --- |
| 원칙 | ADV 회의는 대면이 원칙 |
| 팀 단위 반영 | **한 명이라도 비대면이면 팀원 전체가 비대면** |
| 결석 전환 | 비대면 인원을 **결석으로 반영하면 그 회의는 대면으로 인정** |
| 허용 횟수 | 3회. **초과 경고는 두지 않으며 판단은 운영지원팀** |
| 예외 추가분 | 팀별이 아니라 **기수 전체 기준**. 횟수는 대표진 + 운영지원팀 회의로 결정 |

> 판정은 기록자(팀장)가 적용하고 운영지원팀이 컨펌한다. 표시 위치는 팀 헤더와 세션 집계 export다.

### 4.5 행사 출결 `ATT-EVT`

**화면 목적**: 행사별로 참여 등록 인원의 출결을 기록한다.

| ID | 기능 | 설명 |
| --- | --- | --- |
| EVT-01 | 행사 목록 | 등록 행사 조회 · CSV 추출 · 수정 · 삭제 |
| EVT-02 | 행사 등록 | 행사명 · 일자 · 장소 · **유형 선택** · 대상 기수·부문 선택 |
| EVT-03 | 출결 기록 | 유형별 기록 항목에 따라 입력 + 비고 |
| EVT-04 | 출결 요약 | 총 등록 인원 · 상태별 집계 |
| EVT-05 | 참가자 필터 | 기수 · 출결 상태 · 부문 · 이름 검색 |
| EVT-06 | 현장 참가자 추가 | 사전 명단에 없던 참석자 즉시 추가 |
| EVT-07 | 행사 삭제 | 참가자 N명 출결 동시 삭제 — 확인 모달 필수 |

**대상 산정**: `(필참 ∪ 참여) ∩ 선택한 기수·부문`

- 불참 · 미정 인원은 시트에 포함되지 않으며 감점 대상이 아니다.
- 대상은 `ATT-ROSTER`의 참여 상태에서 산정되므로 **행사별 명단 CSV 업로드는 두지 않는다.**

**행사 유형** — 등록 시 선택하며, 유형이 기록 방식과 참여 상태 초기값을 결정한다.

| 유형 | 해당 행사 | 기록 방식 | 참여 상태 초기값 |
| --- | --- | --- | --- |
| 일반형 | 컨퍼런스톡, 홈커밍데이, MT, 해커톤 등 | 3.2절 상태값 | 전원 미정, 필참은 운영지원팀 지정 |
| 신입 특칙형 | 신입 대상 OT · 컨퍼런스 | 전용 세트 — 출석 / 지각·조퇴 / 인정 지각·조퇴 / 인정결석 / 결석 / 불가항력 인정. 온라인 진행 시 "1차만 출석" · "2차만 출석" 추가 | 신입 기수 전원 자동 필참 |
| 1·2차 체크형 | 활동기수 대상 컨퍼런스 | 상태 대신 **체크 2개** (1차 O/X, 2차 O/X) | ADV 기수 전원 자동 필참 (수료 요건 반영) |

**출결 시트 구성**: `기수 / 부문 / 이름 / 기록 항목 / 비고`

- 일반형 · 신입 특칙형 — 기록 항목은 출결 상태 1개
- 1·2차 체크형 — 기록 항목은 1차 체크 · 2차 체크 2개

**복수 등록 원칙**: 실제 행사 하나를 대상별로 분리 등록한다.

- 예: 컨퍼런스(신입) 특칙형 + 컨퍼런스(활동기수) 체크형
- 예: OT(신입) 특칙형 + OT(멘토·대표진) 일반형

> 신입 특칙형의 결석은 **선발 취소 대상 표시까지만** 담당하고, 처분은 운영지원팀이 한다 (회칙 2장 1조 5항).

### 4.6 스터디 출결 `ATT-STD`

**화면 목적**: 스터디별 회차 그리드를 확인하고, 스터디장이 제출한 인증을 컨펌한다.

| ID | 기능 | 설명 |
| --- | --- | --- |
| STD-01 | 스터디 목록 | 등록 스터디와 제출·진행 상태 |
| STD-02 | 회차 그리드 | 1회차 ~ 총 횟수, 회차별 진행 날짜 기록 |
| STD-03 | 인증 컨펌 | 제출 건 확인 / 반려 (6.1절) |
| STD-04 | 직접 정정 | 운영지원팀 직접 수정 |
| STD-05 | 출석률·판정 표시 | 출석률과 이수/개근/미이수 판정 (5.3절) |

**회차 운영 규칙**

- **보강은 별도 개념을 두지 않는다.** 날짜가 밀린 다음 회차로 취급한다.
- **하루 2회차**는 같은 날짜로 두 회차를 기록한다. "스터디당 1번" 준수 확인은 컨펌 시 운영지원팀이 담당한다 (회칙 8장 1조 7항).
- 무효 주차에는 진행·인증 의무가 없다.

### 4.7 리더 전용 출결 입력 `ATT-LDR`

**화면 목적**: ADV 팀장 · 스터디장이 담당 그룹의 출결과 인증 사진을 제출한다. 운영지원팀 화면과 분리된다.

| ID | 기능 | 설명 |
| --- | --- | --- |
| LDR-01 | 담당 그룹 목록 | 본인이 맡은 팀·스터디. 겸임 시 ADV·스터디 모두 표시 |
| LDR-02 | 출결 입력 | 주차(ADV) / 회차(스터디) 선택 → 명단 → 상태 선택 + 비고 |
| LDR-03 | 인증 사진 제출 | 사진 업로드 후 제출 → 상태 `확인 대기` |
| LDR-04 | 제출 상태 확인 | `미제출` / `확인 대기` / `확인` / `반려` |
| LDR-05 | 반려 확인·재제출 | 반려 사유 확인 후 수정·재제출 |

- 진입 시 현재 운영 구간·주차를 자동 선택한다 (API-03).
- **삭제 권한은 없다.** 주차가 지난 건의 수정도 불가하며, 정정은 운영지원팀에 요청한다.
- 반려 통보는 시스템 알림 없이 **화면 상태 표시**로 하고, 통보는 운영지원팀이 직접 한다.

### 4.8 출결 점수 집계 `ATT-SUM`

**화면 목적**: 세션 · 행사 · 스터디 출결 결과를 회원 기준으로 모아 본다.

| ID | 기능 | 설명 |
| --- | --- | --- |
| SUM-01 | 집계 조회 | 회원 × 활동별 결과와 점수 소계 |
| SUM-02 | 집계 단위 선택 | Term 전체 / 방학 / 학기 (5.4절) |
| SUM-03 | 필터 | 기수 · 부문 · 활동 · 그룹 |

- **중간 합산은 화면 조회로만 제공**하고, export는 최종 집계 3종만 지원한다.
- 무단지각 환산분이 표시 수치와 export에 반영된다 (5.2절).

### 4.9 개인 상세 타임라인 `ATT-TL`

**화면 목적**: 회원 한 명의 출결·점수 이력을 시간순으로 확인한다. 점수 이의 제기 시 근거 확인용이다.

| ID | 기능 | 설명 |
| --- | --- | --- |
| TL-01 | 세션별 출결 이력 | 주차·회차 단위 상태, 기록자(HOST / 운영지원팀), 수정 이력 |

| TL-04 | 적용 규칙 표시 | 각 점수에 적용된 Term 규칙 |

### 4.10 스터디·팀 관리 `ATT-GROUP`

**화면 목적**: 인증 그룹(스터디 · ADV 팀)을 생성하고, 장을 지정하고, 장 계정을 발급한다.

| ID | 기능 | 설명 |
| --- | --- | --- |
| GRP-01 | 그룹 목록 | 스터디 / ADV 팀 구분 조회 |
| GRP-02 | 스터디 등록 | 멘멘 / 일반 구분 · 스터디명 · 스터디장 · **계획서상 총 횟수** |
| GRP-03 | ADV 팀 등록 | 팀명 · 부문 · 팀장 |
| GRP-04 | 장 지정 | 그룹당 1인. `ATT-ROSTER`의 스터디장 여부에 자동 반영 |
| GRP-05 | 계정 발급 | 장 계정 생성 (`role=HOST` · `teamName=그룹리더`), 기존 계정이면 권한만 추가 |
| GRP-06 | 계정 회수 | 기수말 회수 — soft delete + 토큰 정리 |
| GRP-07 | 총 횟수 정정 | **운영지원팀만 가능** (회칙 8장 1조 6항 — 회칙상 변경 불가 항목) |

- **총 횟수는 필수 입력**이며 출석률 분모가 된다 (5.3절).
- 계정 발급 시 기존 계정 존재 여부를 이름·기수·부문으로 확인하고, 있으면 **ID/PW 재발급 없이 리더십만 추가**한다. 스터디를 여러 개 맡으면 리더십 행이 여러 개다.

### 4.11 Term 설정 · 점수 규칙 `SET-RULE`

**화면 목적**: Term 단위 설정값과 점수 규칙을 관리한다.

| ID | 기능 | 설명 |
| --- | --- | --- |
| RULE-01 | Term 설정 | 방학·학기 기간, 주차별 진행 날짜 |
| RULE-02 | 무효 주차 지정 | 해당 주차를 모든 활동 출결 대상에서 제외 |
| RULE-03 | 점수값 설정 | 상태별 점수 (5.1절 기본값) |
| RULE-04 | 행사 단위 오버라이드 | 특정 행사 시트의 점수값을 개별 설정 |
| RULE-05 | Term별 규칙 보관 | Term 단위로 규칙을 보관해 지난 Term 집계를 보존 |

**설정 원칙**

- 점수값은 **Term 단위 설정**이며 기본값은 회칙·규칙표 수치다.
    - Term 단위인 이유: **회칙 개정 시에도 지난 Term 집계가 보존되어야 하기 때문**
- **행사 단위 오버라이드**를 지원한다. 예: OT(멘토) 시트의 결석 점수를 −5로 (멘토 특칙, 회칙 8장 1조 1항)

> 구현 방식(Term 보관 구조 + 행사 오버라이드 계층)은 백엔드 검토 중이다. (→ 9장)

## 5. 점수 계산 규칙

### 5.1 기본값 통합표

| 구분 | 항목 | 기본값 | 출처 |
| --- | --- | --- | --- |
| 세션·행사 공통 | 출석 / 인정결석 / 비대면 / 미기록 | 0 | 회칙 9장 1조 |
| | 지각 / 무단지각 / 조퇴 | −1 | 회칙 9장 1조 |
| | 사유결석 | −3 | 회칙 9장 1조 |
| | 무단결석 | −4 | 회칙 9장 1조 |
| | 무단지각 3회 묶음 (치환) | −4 | 회칙 9장 1조 6항 |
| 신입 특칙형 | 지각·조퇴 | −15 | 회칙 2장 1조 5항 |
| | 인정 지각·조퇴 | −5 | 회칙 2장 1조 5항 |
| | 인정결석 | −10 | 회칙 2장 1조 5항 |
| | 결석 | 선발 취소 표시 | 회칙 2장 1조 5항 |
| | 불가항력 인정 | 0 | 회칙 2장 1조 5항 |
| | 온라인 1차만 출석 / 2차만 출석 | −1 / −3 | 회칙 2장 1조 6항 |
| 1·2차 체크형 | 체크당 (최대 +2) | +1 | 회칙 9장 2조 5항 |
| | 둘 다 미체크 | 결석 처리 후 일반 감점 | 회칙 2장 1조 6항 준용 |
| 스터디 | 개근 (출석률 100%) | +3 | 규칙표 |
| | 이수 (70% 이상 100% 미만) | +1 | 규칙표 |
| | 스터디장 | +1 | 규칙표 |
| | 미이수 (이수 스터디 0개) | −5 | 회칙 8장 3조 4항 |
| | 이수 1개 이상 + 추가 스터디 70% 미만 | −3 | 규칙표 |

### 5.2 무단지각 환산

- **그리드 기록은 원본을 보존**하고, 환산은 집계 계산에서만 적용한다. 주차별 원본이 남아야 정정·추적이 가능하다.

| 항목 | 계산식 |
| --- | --- |
| 표시 무단지각 횟수 | 원본 무단지각 mod 3 |
| 표시 무단결석 횟수 | 원본 무단결석 + (원본 무단지각 ÷ 3의 몫) |
| 점수 | 묶인 3회는 −1×3이 아니라 **−4로 치환**, 3회 단위 반복 |

- 예: 무단지각 4회 + 무단결석 1회 → 표시는 무단지각 1회 / 무단결석 2회 / 점수 −9
- 환산분은 **제명 카운트**(무단결석 3회, 회칙 9장 1조 7항)와 export 수치에 반영된다.

### 5.3 스터디 판정

- 출석률 = **출석 회차 수 ÷ 계획서상 총 횟수**
- Term 말 기준으로 회원별 자동 판정하며, 점수는 5.1절 표를 따른다.
- 스터디장 가점은 `ATT-GROUP`의 장 지정 정보 기반으로 자동 부여한다.

### 5.4 집계 단위

- Term 전체 및 **방학·학기 분할** (중간 집계는 방학 분할본 사용)
- 중간 크기 합산은 화면 조회로 제공하고, export는 최종 집계만 지원한다.

## 6. 운영 플로우

### 6.1 인증 컨펌 (인증 그룹: 스터디 · ADV 팀)

```
미제출
  └ 장이 출결 + 인증 사진 제출 → 확인 대기
                                   ├ 운영지원팀 확인 → 확인 (이 시점에 출결이 기록에 반영)
                                   └ 운영지원팀 반려 → 반려
                                                        └ 장이 재제출 → 확인 대기
```

| 단계 | 내용 |
| --- | --- |
| 제출 | 장이 해당 주차 출결(스터디는 그 주 진행 회차)과 인증 사진 제출. 상태 `확인 대기` |
| 컨펌 | 운영지원팀 확인 시 상태 `확인`. **이 시점에 출결이 기록에 반영**된다 |
| 반려 | 문제 발견 시 상태 `반려`, 장이 재제출 |
| 정정 | 확인 이후에도 운영지원팀은 직접 정정 가능 |

- BASE 세션 · 행사는 이 플로우 없이 **직접 기록**한다.
- 반려 이력은 1차에서 최신 상태만 보관한다.

### 6.2 명단 변경 정책

| 상황 | 처리 |
| --- | --- |
| 출결 기록이 있는 인원을 **불참으로 변경** | 경고 후 확인을 받고 **기록 삭제** |
| 기록 없는 인원의 변경 | 즉시 처리 |
| 병행 포기 | 이후 주차를 **미기록(—)** 으로 두어 계산에서 제외하고, 명단 비고에 기록. 포기·Term 판정 점수는 시스템 밖 |

### 6.3 Term 라이프사이클

| 시점 | 동작 |
| --- | --- |
| Term 시작 | CSV import로 명단 신규 등록 (**기수 전이 로직 없음**) |
| Term 중 | 무효 주차 설정, 출결 기록·컨펌 |
| 방학 종료 | 방학 분할 집계 export (중간 집계) |
| Term 종료 | 최종 집계 export, 해당 Term 데이터는 **조회 전용 아카이브** 전환 |

> **기수 전이 미지원 사유**: BASE에서 ADV로 넘어간 인원도 새 명단에 ADV로 재등록한다. 휴동·복동·수료 실패 등 엣지 케이스를 등록 시점의 운영지원팀 판단으로 흡수한다.

## 7. CSV 입출력

### 7.1 Import (1종) — 명단 일괄 등록

| 항목 | 내용 |
| --- | --- |
| 컬럼 | 기수 / 부문 / 이름 + 속성 컬럼 (3.3절) |
| 빈 값 | **미정(—) 처리** — Term 초에 모든 속성이 확정되지 않는 상황 대응 |
| 검증 | 헤더 불일치 거부 · 이름 누락 행 오류 · 중복 경고 · 오류 시 전체 미반영(all-or-nothing) |
| 결과 | 성공 N건 / 실패 N건, 실패 항목은 행 번호 + 사유 |

### 7.2 Export (3종) — 최종 집계

- 대상: 전 동아리원. 집계 단위는 5.4절
- 용도: 기존 중간·최종 집계 시트의 입력값

| 종류 | 컬럼 |
| --- | --- |
| 세션 집계 | 기수 / 부문 / 이름 / 결석 / 무단결석(환산 포함) / 지각·조퇴 / 비대면횟수(ADV) / 점수 소계 |
| 행사 집계 | 기수 / 부문 / 이름 / 행사별 결과 / 점수 소계 |
| 스터디 집계 | 기수 / 부문 / 이름 / 스터디명 / 스터디장 여부 / 출석률 / 판정 / 점수 소계 |
