## 1. 문서 목적

- 콘텐츠 관리 영역의 **현재 구현된 화면과 기능을 기능 단위로 정리**한다.
- 디자인 단계에서 다시 정리해야 할 항목(노출 필드, 등록·수정 동작, 상태 처리, 작업 동선)을 미리 식별한다.

> **전제**: 현재 화면은 UI/UX 디자인 작업 전 **PoC 수준의 구조안**이다.
> 최종 디자인 단계에서 백엔드 API 명세에 맞춰 노출 필드와 동작을 재정리하고,
> 서비스운영팀의 실제 작업 동선을 검토한 뒤 확정한다.
> 따라서 본 문서의 4장은 **현재 상태 기록**이며, 화면 레이아웃 자체는 확정 명세가 아니다.

## 3. 공통 사항

### 3.1 API 현황

콘텐츠 관리 영역의 조회 API와 CUD API는 **모두 이미 구현되어 있다.** 관리자 화면은 기존 API를 연동하는 작업에 해당한다.

| 구분 | 내용 |
| --- | --- |
| 조회 API | 공식 웹사이트에서 사용 중인 목록 조회 API를 그대로 활용. **페이지네이션 적용 완료**, 인증 없이 호출 가능한 **Public API** |
| CUD API | 기존 구현된 등록 / 수정 / 삭제 API를 관리자 화면과 연동 |

> 관리자 화면이 Public 조회 API를 그대로 사용하는 구조이므로, **관리자 전용 필드(미노출 항목, 작성 메타 등)가 필요한 경우 별도 확인이 필요**하다. (→ 6장)

### 3.2 반영 경로

관리자 페이지에서의 등록·수정·삭제는 **공식 웹사이트 노출에 직접 반영**된다. 별도 배포나 승인 단계가 없다.

## 4. 화면별 기능 명세

### 4.1 아카이브 > 아카이빙 `CNT-ARC`

**화면 목적**: BOAZ 활동 및 프로젝트 아카이빙 콘텐츠를 관리자 페이지에서 관리한다.

**기능 목록**

| ID | 기능 | 설명 |
| --- | --- | --- |
| ARC-01 | 목록 조회 | 현재 등록된 아카이빙 콘텐츠 확인 |
| ARC-02 | 업로드 | 신규 아카이빙 콘텐츠 등록 (`새 항목`) |
| ARC-03 | 수정 | 기존 콘텐츠 정보 수정 |
| ARC-04 | 삭제 | 더 이상 노출하지 않을 콘텐츠 삭제 |

**현재 화면 구성 (PoC)**

- 상단 유형 탭: `프로젝트` / `기술블로그` / `활동사진`
- 필터: 분야, 기수, 키워드 검색 / 조회 건수 표시 (`N건 표시 · 전체 N건`)
- 목록 컬럼: 썸네일, 제목, 기수, 분야, 링크, 노출
- 우측 편집 패널: 선택한 항목의 필드를 즉시 편집
- 하단 페이지네이션 (`이전` / `다음`)

**편집 필드**

| 필드 | 키 | 필수 |
| --- | --- | --- |
| 제목 | `title` | 필수 |
| 팀명 / 작성자 | `team_name` / `author` | 선택 |
| 기수 | `term` | 필수 |
| 날짜 | `contentDate` | 필수 |
| 트랙 | `track` | 필수 |
| GitHub 링크 | `links.github` | 선택 |
| SlideShare 링크 | `links.slideshare` | 선택 |

---

### 4.2 아카이브 > 수료자 후기 관리 `CNT-REV`

**화면 목적**: 웹사이트에 노출되는 수료자 후기 콘텐츠를 관리한다.

**기능 목록**

| ID | 기능 | 설명 |
| --- | --- | --- |
| REV-01 | 목록 조회 | 등록된 후기 콘텐츠 확인 |
| REV-02 | 등록 | 신규 후기 추가 (`새 후기 등록`) |
| REV-03 | 수정 | 기존 후기 내용 수정 |
| REV-04 | 삭제 | 노출이 필요하지 않은 후기 삭제 |

**현재 화면 구성 (PoC)**

- 카드 그리드 형태 (작성자 프로필, 이름·기수, 소속·부문, 후기 본문, 등록일)
- 필터: 분야 선택 + 키워드 검색 / 조회 건수 표시
- 카드별 수정·삭제 아이콘

---

### 4.3 소개 및 안내 > 커리큘럼 관리 `CNT-CUR`

**화면 목적**: 웹사이트에 노출되는 BASE 커리큘럼 정보를 관리한다.

**기능 목록**

| ID | 기능 | 설명 |
| --- | --- | --- |
| CUR-01 | 목록 조회 | 현재 등록된 커리큘럼 정보 확인 |
| CUR-02 | 단계 추가 | 새로운 커리큘럼 단계 추가 (`+ 단계 추가`) |
| CUR-03 | 수정 | 기존 커리큘럼 내용 수정 |
| CUR-04 | 삭제 | 더 이상 사용하지 않는 단계 삭제 |
| CUR-05 | 순서 변경 | 단계 카드의 위·아래 이동 |
| CUR-06 | 일괄 저장 | `전체 커리큘럼 일괄 저장`으로 변경 내용을 한 번에 반영 |

**현재 화면 구성 (PoC)**

- 상단 부문 탭: `데이터 분석(Analysis)` / `데이터 엔지니어링(Engineering)` / `데이터 시각화(Visualization)`
- 단계(Step) 카드 반복 구조, 카드별 순서 이동·삭제 액션
- 저장 시 공식 웹사이트에 즉시 반영된다는 안내 문구 노출

**단계별 입력 필드**

| 필드 | 설명 |
| --- | --- |
| 단계 제목 | 예: `데이터 핸들링 & 탐색적 데이터 분석(EDA)` |
| 학습 내용 및 목표 | 해당 단계의 설명 본문 |
| 다루는 기술 스택 / 툴 | 쉼표로 구분 입력, 입력값이 태그 형태로 표시 |
| 주차 범위 | 카드 상단 표기 (예: `1~3주차`) |

> 다른 화면이 항목 단위 즉시 저장인 것과 달리, 커리큘럼은 **일괄 저장 방식**이다. 디자인 단계에서 저장 방식 통일 여부를 검토한다. (→ 6장)

---

### 4.4 소개 및 안내 > 자주 묻는 질문 (FAQ) `CNT-FAQ`

**화면 목적**: 웹사이트에 노출되는 FAQ 질문과 답변을 관리한다.

**기능 목록**

| ID | 기능 | 설명 |
| --- | --- | --- |
| FAQ-01 | 목록 조회 | 현재 등록된 질문 / 답변 확인 |
| FAQ-02 | 등록 | 새로운 FAQ 항목 추가 (`새 FAQ 등록`) |
| FAQ-03 | 수정 | 기존 질문 또는 답변 내용 수정 |
| FAQ-04 | 삭제 | 사용하지 않는 FAQ 항목 삭제 |
| FAQ-05 | 노출 제어 | 항목별 노출 여부 토글 |

**현재 화면 구성 (PoC)**

- 상단 카테고리 탭: `전체 카테고리` / `리크루팅` / `활동 안내` / `기타`
- 질문 검색 + 정렬 옵션
- 행 구조: 카테고리 배지, 순번, 질문, 액션 아이콘(노출 / 수정 / 삭제 / 펼침)
- 행 펼침 시 답변 본문, 최종 수정일, 우선순위 표시

## 5. API 요구사항

조회·CUD API가 모두 구현되어 있어 **신규 API 요구는 없다.** 다만 디자인 확정 시 다음을 확인한다.

| ID | 확인 항목 | 사유 |
| --- | --- | --- |
| CNT-API-1 | 관리자 전용 필드 필요 여부 | 조회 API가 Public API라 미노출 항목·작성 메타를 담고 있지 않을 수 있음 |
| CNT-API-2 | 노출 토글 필드 존재 여부 | FAQ·아카이빙의 노출 제어를 API가 지원하는지 확인 |
| CNT-API-3 | 이미지 업로드 경로 | 아카이빙 썸네일, 후기 프로필 이미지의 업로드 방식 확인 |

## 6. Open Issues — 디자인 확정 전 정리 필요

현재 화면은 PoC 구조안이므로, 아래 항목을 정리한 뒤 최종 디자인을 진행한다.

| ID | 항목 | 대상 | 정리할 내용 | 주체 |
| --- | --- | --- | --- | --- |
| CNT-B-1 | 노출 필드 확정 | 전체 | 백엔드 API 명세 기준으로 각 화면에 표시·입력할 필드 확정 | PM + BE |
| CNT-B-2 | 등록 / 수정 동작 방식 | 전체 | 인라인 편집 · 우측 패널 · 모달 중 방식 통일 | 디자인 |
| CNT-B-3 | 저장 방식 통일 | 커리큘럼 | 항목 단위 즉시 저장 vs 전체 일괄 저장 | PM + 디자인 |
| CNT-B-4 | 상태 처리 | FAQ · 아카이빙 | 노출 / 비노출 등 상태 값의 정의와 화면 표현 | PM + BE |
| CNT-B-5 | 삭제 확인 단계 | 전체 | 웹사이트에 즉시 반영되는 구조이므로 오삭제 방지 확인 단계 필요 | 디자인 |
| CNT-B-6 | 작업 동선 검토 | 전체 | **인터뷰 대상 = 서비스운영팀(확정).** 일괄 등록 여부 · 원본 자료 출처 · 등록 후 확인 시점 · 현재 불편 지점 확인 | 서비스운영팀 + 디자인 |

> CNT-B-6은 회신형 문의가 아니라 **인터뷰**다. 관리자 페이지를 실제로 쓰는 서비스운영팀과 화면을 함께 보며 확인해야 한다.
